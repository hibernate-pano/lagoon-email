# Lagoon 使用说明（V3：QQ 邮箱 · 单进程嵌入式）

> 这份文档告诉你：从零开始把 Lagoon 跑起来需要什么、每一步会发生什么、出错了怎么排查。
>
> Lagoon 目前只支持 **QQ 邮箱**（授权码接入）。闭环：同步收件箱 → 阅读正文 → Briefing 五分堆 → AI 摘要/回复草稿 → 回复发送 → 归档 / ⌘Z 撤销。
>
> 架构是**单进程**：服务端（Swift/Hummingbird）和 SQLite 存储全部内嵌在 `Lagoon.app` 里。没有 Docker、没有 Postgres、没有 launchd、没有 `.env`。数据只落在这台 Mac 上。

---

## 一、你需要准备什么

| 需要什么 | 说明 |
|------|------|
| 一个 QQ 邮箱 | 在 QQ 邮箱设置里开启 IMAP/SMTP 服务（见下） |
| 一个 **16 位授权码** | 不是 QQ 登录密码，专门给第三方客户端用 |
| Mac（macOS 14+） | 应用是原生 SwiftUI |

日常使用只需要 `dist/Lagoon.app`；从源码跑见第四节。

## 二、QQ 邮箱接入（5 分钟）

### 第 1 步：拿到授权码（一次性，2 分钟）

1. 浏览器登录 [QQ 邮箱网页版](https://mail.qq.com) → 顶部 **设置** → **账户**
2. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务** → **开启服务：IMAP/SMTP 服务**
3. 按提示做手机短信验证 → 页面弹出一串 **16 位授权码**（字母，一般没有空格）
4. 复制保存。**页面关掉后不再显示**，忘了就重新生成一个（旧的立即失效）

### 第 2 步：在 Lagoon 里连接

1. 打开 `Lagoon.app` → 连接页填 **QQ 邮箱地址** + **授权码** → 点 **连接**
2. 连接会转 1～3 秒：服务器先真的连一次 `imap.qq.com:993` 验证凭据，通过了才落库并开始首次同步
3. 授权码两端若有空格/换行会被自动去除（浏览器复制常带尾巴）

连接成功后：

- 工具栏账号菜单里能看到账号和**状态点**：🟢 同步正常 / 🟡 失败重试中 / 🔴 需要重新连接（含义见第五节第 6 条）
- 邮件正文按需从服务器拉取，本地只存已打开过的——第一封打开会稍慢一点
- 详情页 **回复** → 编辑正文 → **⌘↩ 发送**（走 `smtp.qq.com:465`）
- 归档：⌘⌫ / 列表或详情按钮；误操作 **⌘Z** 撤销（远端也会移回收件箱）
- 一键退订：Briefing 里的订阅噪音直接退订（RFC 8058 / 自动确认，全程可撤销性除外——退订不可撤销）

> **授权码安全**：授权码用 AES-GCM 密封后落库（密钥在本机 Keychain），**不会**出现在日志、错误信息或任何 API 响应里；`GET /api/accounts` 只返回地址、同步状态和能力，不返回凭据。

### 第 3 步：填 AI Key（V1 新增，2 分钟）

1. 点窗口右上 ⋯ 菜单 → **AI 设置**（或 ⌘K → AI 设置）。
2. 填 **MiniMax API Key**（接口地址和模型已预填，不用动），再填**每月上限（美元）**，点**保存**。
3. **重启 App**（Key 改动需重启生效，保存页会提示）。

Key 只存本机钥匙串（`lagoon.envJSON`），不清零、不上传。清空 Key = 关掉 AI（摘要/草稿显示"AI 未配置"，邮件不受影响）。

## 三、数据在哪、怎么备份

- 数据库：`~/Library/Application Support/Lagoon/lagoon.sqlite`（含 `-wal`/`-shm`）
- **备份 = 退出 App 后把这一个文件拷走**（WAL 模式下三个文件一起拷最稳妥）
- 密钥：全部在 Keychain（`lagoon.tokenKey`、`lagoon.apiTokenSecret` 等），磁盘上没有含密钥的文件
- 想彻底重来：退出 App，删除上面的目录，重开（Keychain 密钥可保留，数据库会重建）

## 四、开发者：从源码跑起来

| 命令 | 作用 |
|------|------|
| `swift build` | 编译全部目标 |
| `bash scripts/run-all-tests.sh` | 全量自检：安全守卫 → 守卫自测 → 全部测试 → 编译（测试用独立临时 SQLite，**不需要任何数据库服务**） |
| `swift run Lagoon` | 直接跑客户端（内嵌服务端随之启动） |
| `bash scripts/build-app.sh` | 构建可分发的 `dist/Lagoon.app` |

诊断工具（读已连接账号，连真实 IMAP）：

```bash
swift run LagoonServerCLI --list-mailboxes    # 列出服务器上的所有文件夹
swift run LagoonServerCLI --self-test         # SMTP 发送→同步→归档→还原闭环（只发给自己）
python3 scripts/probe-qq.py <邮箱地址>         # 用授权码连一次真实 QQ，打印 Lagoon 会解析出的角色文件夹
```

CLI 走环境变量契约：`LAGOON_TOKEN_KEY`（32 字节 base64，加密凭据用）必填；要与 App 共享数据，用它 Keychain 里 `lagoon.tokenKey` 的值。

## 五、常见问题排查

**1. QQ 连接报「授权码被拒绝」**
→ 授权码不是登录密码；而且在 QQ 设置里**每重新生成一次，旧的立即失效**。去第 1 步重新生成一个再试。
→ 确认码是新的还报错：检查 IMAP/SMTP 服务是不是被 QQ 关掉了（长期不用会自动关闭），重新开启即可。
→ 这类错误会让同步状态进入 🔴 并**停止重试**（QQ 对连续失败登录会限流，所以是刻意不重试的）：重新连接成功后自动恢复。

**2. QQ 连接报「无法连接 QQ 邮箱服务器」**
→ 服务器连不上 `imap.qq.com:993`。先验证网络：`nc -vz imap.qq.com 993`。
→ 常见原因：公司网络/代理只放行 443。Lagoon 只走 **993（IMAP）和 465（SMTP）两个 implicit-TLS 端口，没有「跳过证书校验」开关**——这是安全边界，不会为连通性放宽。连接主机固定来自服务端 preset（`imap.qq.com` / `smtp.qq.com`），不接受任意主机。
→ 注意：如果你的代理开着 fake-ip 模式的 TUN，`dig` 出来的地址是假的（198.18.x.x），这不影响 Lagoon 本身连接，但会让你手工诊断时误判。

**3. 客户端显示 "Sync failed: …"，或者列表为空**
→ 先确认内嵌服务端在跑：`curl http://127.0.0.1:8080/healthz` 应返回 `ok`（若 8080 被占，App 会自动换 8081–8090，端口显示在「关于」里）。
→ 状态点变 🔴：授权码被拒，重新 Connect。

**4. 归档按钮是灰的 / 提示「没有可用的归档文件夹」**
→ 服务器在接入时协商过能力：既没有 `\Archive` 特殊文件夹，也没找到名为「归档 / Archive」的文件夹时，`capabilities.archiveFolder = false`，客户端据此禁用归档（服务端也会 409 拒绝，不会「半个归档」）。
→ 撤销入口（⌘Z / Undo 面板）**不受这个门控影响**——已归档的内容照样能撤销。

**5. 想验证归档/删除会用哪个服务器文件夹**
→ 跑 `python3 scripts/probe-qq.py`：它打印 QQ 返回的原始文件夹列表、modified UTF-7 解码结果，以及 Lagoon 当前匹配逻辑会选中的归档/废纸篓/已发送文件夹。中文文件夹名在 IMAP 协议里是 modified UTF-7 编码（`归档` = `&X1JoYw-`），这是国内邮箱兼容性最需要盯的点。实测 QQ 返回的是英文文件夹名（Archive / Sent Messages / Deleted Messages），所以这一层目前没有实际风险，但换服务商时仍要用这个脚本确认。

**6. 账号菜单上的状态点是什么意思？**
→ 数据来自 `GET /api/accounts` 的 `syncHealth`：

| 状态点 | 状态值 | 含义 | 服务器行为 |
|--------|--------|------|-----------|
| 🟢 | `ok` | 同步正常 | 持续同步（IDLE 或轮询） |
| 🟡 | `degraded` | 连续 3 轮失败，正在退避重试 | 1→2→…→300 秒退避（±20% 抖动）后重试 |
| 🟡 | `error` | 单轮失败（网络抖动等） | 同上，失败原因在菜单项里显示 |
| 🔴 | `needsReconnect` | 授权码被拒 | **停止重试**，重新连接后恢复 |

## 六、代码在哪一层

```
Sources/LagoonKit      ← 两端共享的类型 + LagoonDatabase.swift（SQLite 表结构就在这里）
Sources/LagoonServer   ← Hummingbird 服务器：IMAP/SMTP、同步引擎、API 路由
Sources/Lagoon         ← macOS SwiftUI 客户端
Sources/LagoonAI       ← LLM 网关（MiniMax，OpenAI 兼容协议）
docs/superpowers/      ← 历史归档：产品 spec、实施计划、冒烟测试记录
```

> 注意：改表结构只改 `Sources/LagoonKit/LagoonDatabase.swift` 里的内联 schema——没有独立的迁移 SQL 目录，也没有迁移脚本。

## 七、当前边界（明确不做的）

- **AI 只建议，不操作**：AI 读邮件、分类、解释、生成草稿文本。它不会自动归档/删除/退订/标已读，不会自己建规则，更不会发送邮件。所有改动都由你点击触发，并进入撤销记录
- **看 AI 建议**：按 ⇧⌘A，或从「⋯」菜单打开「AI 建议」。面板里每条建议会说明是什么邮件（营销 / 垃圾 / 工作 / 财务…）、AI 认为该做什么、以及它有多确定。你可以「忽略这条」或「查看邮件」——**面板本身没有任何会改动邮件的按钮**，归档和删除仍然在简报行和邮件详情页操作，由你亲手点
- 忽略一条建议后，即使 AI 重新分析这封邮件也不会再推给你
- 只支持 QQ 邮箱（Gmail 路线已移除；将来需要时作为新 feature 开发）
- iOS 客户端：未做
- 附件下载：已做，单个附件上限 25MB
- 正文本地缓存：已做，只存打开过的邮件（关闭后重开不再走网络）
- 邮件正文渲染不加载任何远程图片/外链资源（发件人无法据此知道你读过）
- 快捷键：⌘R = 回复，⇧⌘R = 回复全部，⌥⌘R = 刷新（详情页里也能刷）；标为未读已修好，行菜单/⋯菜单都能用
- 分发需要 Developer ID 签名 + 公证；当前包是临时签名（ad-hoc），仅限本机/可信机器
- 邮件数据不出本机；只有 AI 摘要/草稿的相关文本会发给你配置的模型服务商
