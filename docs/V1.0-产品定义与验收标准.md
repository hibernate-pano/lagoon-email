# V1.0 · 产品定义与验收标准

> 更新：2026-11-02 · 对象：Rust 产品（`shell/` + `web/` + `crates/`）
> 用途：唯一验收尺子。每一条都能用下面的命令验证；验证不了的不写进来。
> 旧版（Swift 时代）已归档到 `docs/archive/v3/`。

---

## 一、这是什么产品

**一句话**：装在自己 Mac 上的邮件分诊机。早上打开两次，每次十分钟，把收件箱清到零。

**形态**：

- 单机 macOS 应用，`dist/Lagoon.app` 一个包。
- 进程结构：Tauri 外壳（窗口/监督/IPC 代理）+ Web 前端 + Rust 后端（HTTP、同步、SQLite）。
- 数据与密钥只在本机；前端不持有 API token。

**它不是什么**（刻意的非目标，不是缺口）：

- 不是 Gmail/Outlook 的替代品，不做多协议、不做团队协作、不做移动端。
- 不自动化：没有后台归档、没有自动退订、没有自动标记已读、没有 AI 自动发信。

## 二、能力边界（必须如实标注）

| 能力 | 现在的事实 |
|---|---|
| 读路径 | 列表 / 计数 / 简报 / 阅读器 / 搜索 / 导出 / 草稿 / 内联图已实现 |
| **附件** | ✅ 阅读器里点附件即存到 `<数据目录>/downloads/` 并在访达里显示；同名不覆盖；**不自动打开**。字节不走 JSON 代理，走外壳的 `download` 命令（IPC 契约 §4.5） |
| 正文 | 缓存优先；未缓存的邮件在首次打开时抓取并落库 |
| 账号 | IMAP 连接、激活、删除；重新认证后同步循环自动恢复 |
| 同步 | UIDVALIDITY、指数退避、单写者；IDLE 已接线（单次等待 290s）；手动同步入口已有 |
| 写路径 | 归档 / 取消归档 / 废纸篓 / 恢复 / 彻底删除 / 已读 / 置顶 / 批量 / 清空 / 审计 / 撤销 |
| **AI** | ✅ 只读顾问：摘要 / 起草 / 分诊建议（`/summary`、`/draft`、同步分诊）；`/api/ai-status` 如实报告是否配置。没配 key 时 AI 路由 503 `ai-not-configured`，其余功能不受影响。AI 永不写邮箱、永不发信 |
| **发送** | ✅ 回复 / 新建 / 转发（`/reply`、`/compose/send`、`/forward`）**已有界面**：标题栏「写邮件」、阅读器「回复 / 转发」、快捷键 `c` / `r`；`requestId` 是幂等键，同一次请求只发一封 |
| 平台 | 仅 macOS；Developer ID 签名、自动更新、Windows/Linux 未做 |

**AI 一栏的验收口径**：`/api/ai-status` 在设置了 `LLM_PROVIDER_PRIMARY_API_KEY` 时返回 `configured:true`，摘要/起草路由返回真实文本；没设置时返回 `configured:false` 并且 AI 路由如实 503——两条路径都有测试，不存在「假装在工作」。**发送一栏的验收口径**：一个 `requestId` 对应一封 SMTP `MAIL FROM/RCPT TO/DATA`；同一个 requestId 重放返回首次结果，不再发信。

## 三、四条核心承诺

| 承诺 | 含义 | 怎么验证 |
|---|---|---|
| **P1 · 十分钟清零** | 列表、计数、简报三者一致；空态能区分「没有邮件」「没有匹配的邮件」「数据拿不到」 | 见下方命令 |
| **P2 · 撤销是真的** | 撤销归档/删除必须让邮件回到原处，且远端与本地同时回退 | 见下方命令 |
| **P3 · 不撒谎** | 界面上任何状态都能回答「后端此刻的真实状态是什么」；答不出就显示「不知道」 | 见下方命令 |
| **P4 · 能读信** | 打开一封从未抓取过的邮件，必须拿到正文（并落库，第二次走缓存） | 见下方命令 |

### P1 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test contract_replay
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths
cd web && npx vitest run src/core/__tests__/errors.test.ts
```

- `contract_replay`：列表、计数、简报的响应形状与抓取时的真实响应逐字节一致。
- `errors.test.ts`：`emptyStateFor` 只在**已知 0** 时给空态文案；`total === null`（不知道）不算空。
- 前端空态三分支在 `web/src/screens/MessageList.tsx`：已知 0 → 该视图的空文案；有搜索词且 0 条 → 「没有匹配」；数据不可用 → 错误/重试，不渲染成空。

### P2 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_actions \
  undo_of_an_archive_unarchives_locally_and_remotely
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_actions \
  undo_of_a_delete_restores_locally_and_remotely
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_actions \
  undo_of_an_unarchive_rearchives_locally_and_remotely
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_actions \
  undo_of_a_restore_rethrashes_locally_and_remotely
```

四条测试同时断言本地行与远端调用：撤销走的是逆动作（归档↔取消归档、删除↔恢复），
不是重放原动作。后两条钉的是「逆操作本身被撤销」——审计记录必须区分方向，否则撤销取消归档会变成再取消一次。

### P3 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths
cd web && npx vitest run src/core/__tests__/errors.test.ts
```

- 每个 Rust 路由能返回的错误码，在前端字典里都有一句人话（缺一条该测试变红）。
- 401 / 403 / 404 / 503 各自有不同说法，不共享「操作失败」。
- 后端没有 token 时**拒绝启动**；没带 token 的请求一律 401（见「安全」）。

### P4 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_bodies
cargo test --manifest-path crates/Cargo.toml -p lagoon-mail --test imap_provider \
  fetch_raw_message_finds_an_archived_message_after_inbox_says_gone
```

五个用例：缓存缺失 → 抓取 + 落库 + 200；抓取失败 → 502 且不缓存；消息确实不存在 → 410
`message-gone` 且不缓存；凭据解不开 → 503；未知账号 → 404 且不发起抓取。

provider 级用例钉住「归档后打开未缓存的正文」：INBOX 找不到时按 Message-ID 依次在
Archive / Trash 角色文件夹里再找，而不是把已归档邮件报成 502。

**正文打开的快速路径（2026-11-02 真实邮箱只读实测后补）**：

- 同步时把服务器 UID 落库（`message_headers.remote_uid`，migration `lagoon-v11`）；打开 INBOX
  邮件直接 `UID FETCH <uid>`，不再走「Message-ID 搜索（QQ 恒返回空）→ 全邮箱扫描」。
- UID 只在一个 mailbox / UIDVALIDITY 内有效：取回后核对 Message-ID，不符或已消失就回退到身份解析
  （provider 用例 `fetch_body_ignores_a_stored_uid_that_now_holds_another_message`）。
- 归档/删除的本地行不复用该 UID（UID 是文件夹本地的）；成员遍历顺带为老行补 UID
  （`fill_remote_uids`），老库不必重同步。
- 真实邮箱（419 封）只读实测：无 UID 提示 3.8s，有提示 1.2s（其余为连接与正文传输）。
  测量命令：`cargo run -p lagoon-api --example imap_probe -- --db <库> --keys <keys.json>`。
- 未覆盖：归档/废纸篓里的邮件仍走身份解析（没有记录目标文件夹的 UID），首次打开约 3.8s。

## 四、同步与 IDLE

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_sync
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_reconnect
```

必须成立的事实：

- IDLE 预算非零且真的写进协议命令流；服务端不支持 IDLE 时 `waited=false`，循环退回 300s 轮询，不紧循环。
- 账号因认证失败 park 后，重新认证能重启同步循环（`r3_reconnect`）。

**IDLE 超时的错误分类（2026-11-02 真实邮箱只读实测后修）**：

- Unix 的 `SO_RCVTIMEO` 超时返回 `WouldBlock`（EAGAIN），Windows 返回 `TimedOut`。传输层原先只把
  `TimedOut` 当超时，于是 IDLE 在预算耗尽时把正常超时当成不可达错误，整轮同步失败——真实邮箱上
  每轮恰好在 290s 后 `sync.failed label=unreachable`，新邮件永远不入库。
- 现在两种错误都归一为 `TimedOut`（`lagoon-mail/src/error.rs`，单测
  `a_unix_socket_read_timeout_is_a_timeout`）；真实邮箱复测：`IDLE 60s: ok events=0`，
  随后的 `SELECT` 正常返回（探测命令
  `cargo run -p lagoon-api --example imap_idle_probe -- --db <库> --keys <keys.json> --idle 60`）。

## 五、AI 只读与发送

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r4_ai
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r4_triage
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_send
```

必须成立的事实：

- **AI 只读**（`the_ai_never_touches_the_mailbox`）：摘要与起草全程没有一个 IMAP 写动词被调用；
  建议只写 `advice`（`source='ai'`、`decision='pending'`），从不写 `ai_actions`。
- **不重复收费**：同一封邮件的摘要只买一次（第二次读缓存）；已经有建议的邮件不再问模型
  （`a_mail_that_already_has_a_suggestion_is_not_asked_about_again`）。
- **没配 key 不假装**：`/api/ai-status` 返回 `configured:false`，摘要/起草 503 `ai-not-configured`，
  且一个请求都不发。
- **预算闸门**：本月账本花费达到 `LAGOON_BUDGET_USD_PER_MONTH` 后，调用在离开本机之前被拒
  （503 `ai-budget-exceeded`）；0 表示「没设上限」，不是「上限为 0」。
- **发送幂等**：一个 `requestId` 只发一封（`the_same_request_id_sends_once_and_replays_the_first_result`）；
  同一 key 并发 → 409 `send-in-flight`；重放同 key → 返回首次结果。
- **发信前拒**：收件人 / 附件 / 请求体不合法在 SMTP 之前就 400（`an_invalid_recipient_is_refused_before_smtp` 等），
  不会发出半封信；转发拿不到原信时 502，而不是转一封残缺的信。

### 发信界面的验收口径（前端）

```bash
cd web && npm test && npm run typecheck && npm run build
```

- **三个入口**：标题栏「✎ 写邮件」、阅读器「↩ 回复」「⇉ 转发」、快捷键 `c` / `r`。
- **形状对路**：新建用 `to` 字符串，回复 / 转发用 `to` 数组（服务端自己拆 `"名字" <a@b>` 这种地址，
  前端不猜地址从哪结束）；转发永远不带附件（原信本身就是附件）。
- **幂等键的语义**（`web/src/core/send.ts`，38 个测试）：结果未知时重试**复用**同一个 `requestId`
  （服务端回放第一次的结果，不会发第二封）；被明确拒绝后重试**换新** `requestId`
  （服务端会回放失败，换 key 才是真重试）；内容改了就是新的一封信。
- **失败不吃草稿**：任何失败之后收件人 / 主题 / 正文都还在，改一下再发是一键的事。
- **不发时不动邮箱**：收件人不合法时前端先拦，服务端在 SMTP 之前再拦一次——两头都不会发出半封信。

## 六、安全底线

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths \
  a_server_without_a_token_refuses_every_gated_path
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths \
  host_guard_and_auth_gate_match_v3
```

- `LAGOON_API_TOKEN` 缺失 → 后端拒绝启动。
- 人为构造的无 token 服务器 → 所有 gated 路径 401（fail-closed）。
- Host 不在白名单 → 403；`//healthz` 这种可能被路由归一化的拼写也必须被拦。
- 后端自绑端口并通过 stdout 报给外壳，外壳不再自选端口（避免 token 发给抢占端口的进程）。
- 外壳 CSP：`web/index.html` 的 meta 是实际执行面（WebKit 忽略 `tauri://` 的 CSP 响应头），`shell/tauri.conf.json` 保留给其他平台。

## 七、六态与三个「不知道」

每个会等待数据的界面必须显式处理六态（`web/src/core/async.ts`）：

| 状态 | 必须做到 |
|---|---|
| 加载中 | 有可见反馈，不能转圈后什么也没发生 |
| 空 | 一句人话 + 一个下一步动作 |
| 错误 | 说清发生了什么 + 能做什么 |
| 离线 | 明示离线；动作给出原因 |
| 未连接 | 有连接入口 |
| 部分成功 | 报出真实的剩余数 |

三个「不知道」，说错即违约：

1. **未探测 ≠ 否**（能力没探测过 ≠ 不支持）。
2. **读不到 ≠ 不存在**（凭据解不开 ≠ 账号没保存）。
3. **没设过 ≠ 设成了 0**（预算没填 ≠ 上限是 0）。

源码位置：`web/src/core/errors.ts`（错误码字典）、`web/src/core/empty.ts`（空态规则）、
`web/src/core/async.ts`（六态阶梯）。

## 九、「成熟」的判据（终审用）

一个不是 demo、不是 hackathon 项目的产品，在**不知情的人**手里应该表现为：

1. 打开有窗口，不卡死，不报错，不显示内部变量名。
2. 每个按钮按下去都有可见的结果，包括失败。
3. 界面上没有一句话是假的。
4. 关掉再开，状态还在。
5. 出错时用户知道自己该做什么。
6. 拿给别人看，说得出它是什么、为什么这样设计。

**六条全中 = V1.0 可交付。缺一条都还在 V0.9。**
