## 一、结论摘要

| 严重度 | 数量 | 说明 |
|---|---|---|
| **P0 崩溃** | 2 | 2 个文件、共 3 处运行时强解包崩溃（`NSApp.mainWindow!` ×2、`.first!` ×1） |
| **P1 功能缺陷** | 7 | 置顶/未读透镜不生效、三个死代码导致 UI 承诺落空、Server 句柄可能丢失、逐条 Task 扇出无并发上限等 |
| **P2 质量/性能** | 11 | body 内 O(n) 计算、每次击键写 UserDefaults、下标作 ForEach 身份等 |

**最需要立刻处理的三条**：

1. **P0-01/02** —— `MessageDetailView` 两处 `NSApp.mainWindow!` 强解包，在「无窗口」场景（App 刚启动、窗口全关后从通知唤起）直接崩溃。
2. **P1-01** —— 侧边栏「置顶」和「未读」两个入口**在服务端根本没有对应过滤**，点击后渲染的是整个收件箱；侧边栏角标却显示真实数字，用户点进去看到完全对不上的列表。
3. **P1-03** —— `isPurging` 是个写了从不读的死状态，其注释宣称「防止二次点击重复彻底删除」——**这个防护不存在**，而彻底删除是产品里唯一没有撤销的动作。

## 六、并发与 Sendable 专项

以 `-strict-concurrency=complete` 编译 Lagoon 目标，**仅 1 条警告**，无错误：

```
Sources/Lagoon/Views/HTMLMessageView.swift:363:14: warning: instance method
'webView(_:decidePolicyFor:decisionHandler:)' nearly matches optional requirement
'webView(_:decidePolicyFor:decisionHandler:)' of protocol 'WKNavigationDelegate'
```

这条是 WKWebView 在 macOS 14 SDK 上同时提供同步与异步两个重载导致的签名歧义，编译器选择匹配了错误的那个。**潜在后果**：`decidePolicyFor` 可能**永远不被调用** → 远程内容拦截规则失效 → 邮件里的远程图片/脚本被加载（隐私泄漏 + 性能问题）。

**建议**：改用明确的异步重载签名 `webView(_:decidePolicyFor:preferences:decisionHandler:)`，或在同步重载上加 `@available(macOS, deprecated: 15.0)` 标注以消歧。

其余并发相关结论：
- `Package.swift` 未设置 `swiftLanguageVersion`，Lagoon 目标实际以 **Swift 5 语言模式**编译（`-swift-version 5`），因此 `Sendable` 违规只产生警告而非错误
- `AccountStore` / `DirectoryStore` / `UndoController` / `ErrorCenter` / `ColumnWidthStore` 均正确标注 `@MainActor`
- `APIClient` 正确标注 `Sendable`，`URLSession` 与 `URL` 均为 Sendable
- `ColumnSolver` / `RubberBand` 是纯值类型，无共享可变状态
