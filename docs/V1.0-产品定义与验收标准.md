# V1.0 · 产品定义与验收标准

> 更新：2026-11-02 · 对象：Rust 产品（`shell/` + `web/` + `crates/`）
> 用途：唯一验收尺子。每一条都能用下面的命令验证；验证不了的不写进来。
> 旧版（Swift 时代）已归档到 `docs/archive/v3/`。

---

## 一、这是什么产品

**一句话**：装在自己 Mac 上的邮件分诊机。早上打开两次，每次十分钟，把收件箱清到零。

**形态**：

- 单机 macOS 应用，`dist/Lagoon.app` 一个包。
- 进程结构：Tauri 外壳（窗口/监督/IPC 代理）+ Web 前端 + Rust 后端（HTTP、同步、SQLite）。
- 数据与密钥只在本机；前端不持有 API token。

**它不是什么**（刻意的非目标，不是缺口）：

- 不是 Gmail/Outlook 的替代品，不做多协议、不做团队协作、不做移动端。
- 不自动化：没有后台归档、没有自动退订、没有自动标记已读、没有 AI 自动发信。

## 二、能力边界（必须如实标注）

| 能力 | 现在的事实 |
|---|---|
| 读路径 | 列表 / 计数 / 简报 / 阅读器 / 搜索 / 导出 / 草稿 / 内联图已实现 |
| 正文 | 缓存优先；未缓存的邮件在首次打开时抓取并落库 |
| 账号 | IMAP 连接、激活、删除；重新认证后同步循环自动恢复 |
| 同步 | UIDVALIDITY、指数退避、单写者；IDLE 已接线（单次等待 290s）；手动同步入口已有 |
| 写路径 | 归档 / 取消归档 / 废纸篓 / 恢复 / 彻底删除 / 已读 / 置顶 / 批量 / 清空 / 审计 / 撤销 |
| **AI** | **未实现**：`/api/ai-status` 恒返回 `configured:false`；界面显示「未配置」。不提供摘要、分类、起草 |
| **发送** | **未实现（R3.5b）**：协议层 SMTP 已有实现与测试，产品路由未接线 |
| 平台 | 仅 macOS；Developer ID 签名、自动更新、Windows/Linux 未做 |

**AI 一栏不是占位**：任何「AI 只读」「AI 分诊」的措辞都不再成立，直到 `/api/ai-status` 能返回 `configured:true` 并且有对应路由。

## 三、四条核心承诺

| 承诺 | 含义 | 怎么验证 |
|---|---|---|
| **P1 · 十分钟清零** | 列表、计数、简报三者一致；空态能区分「没有邮件」「没有匹配的邮件」「数据拿不到」 | 见下方命令 |
| **P2 · 撤销是真的** | 撤销归档/删除必须让邮件回到原处，且远端与本地同时回退 | 见下方命令 |
| **P3 · 不撒谎** | 界面上任何状态都能回答「后端此刻的真实状态是什么」；答不出就显示「不知道」 | 见下方命令 |
| **P4 · 能读信** | 打开一封从未抓取过的邮件，必须拿到正文（并落库，第二次走缓存） | 见下方命令 |

### P1 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test contract_replay
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths
cd web && npx vitest run src/core/__tests__/errors.test.ts
```

- `contract_replay`：列表、计数、简报的响应形状与抓取时的真实响应逐字节一致。
- `errors.test.ts`：`emptyStateFor` 只在**已知 0** 时给空态文案；`total === null`（不知道）不算空。
- 前端空态三分支在 `web/src/screens/MessageList.tsx`：已知 0 → 该视图的空文案；有搜索词且 0 条 → 「没有匹配」；数据不可用 → 错误/重试，不渲染成空。

### P2 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_actions \
  undo_of_an_archive_unarchives_locally_and_remotely
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_actions \
  undo_of_a_delete_restores_locally_and_remotely
```

两条测试同时断言本地行与远端调用：撤销走的是 `Archive::inverse()` / `Trash::inverse()`，不是重放原动作。

### P3 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths
cd web && npx vitest run src/core/__tests__/errors.test.ts
```

- 每个 Rust 路由能返回的错误码，在前端字典里都有一句人话（缺一条该测试变红）。
- 401 / 403 / 404 / 503 各自有不同说法，不共享「操作失败」。
- 后端没有 token 时**拒绝启动**；没带 token 的请求一律 401（见「安全」）。

### P4 验证

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_bodies
```

四个用例：缓存缺失 → 抓取 + 落库 + 200；抓取失败 → 502 且不缓存；凭据解不开 → 503；
未知账号 → 404 且不发起抓取。

## 四、同步与 IDLE

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_sync
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test r3_reconnect
```

必须成立的事实：

- IDLE 预算非零且真的写进协议命令流；服务端不支持 IDLE 时 `waited=false`，循环退回 300s 轮询，不紧循环。
- 账号因认证失败 park 后，重新认证能重启同步循环（`r3_reconnect`）。

## 五、安全底线

```bash
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths \
  a_server_without_a_token_refuses_every_gated_path
cargo test --manifest-path crates/Cargo.toml -p lagoon-api --test read_paths \
  host_guard_and_auth_gate_match_v3
```

- `LAGOON_API_TOKEN` 缺失 → 后端拒绝启动。
- 人为构造的无 token 服务器 → 所有 gated 路径 401（fail-closed）。
- Host 不在白名单 → 403；`//healthz` 这种可能被路由归一化的拼写也必须被拦。
- 后端自绑端口并通过 stdout 报给外壳，外壳不再自选端口（避免 token 发给抢占端口的进程）。
- 外壳 CSP：`web/index.html` 的 meta 是实际执行面（WebKit 忽略 `tauri://` 的 CSP 响应头），`shell/tauri.conf.json` 保留给其他平台。

## 六、六态与三个「不知道」

每个会等待数据的界面必须显式处理六态（`web/src/core/async.ts`）：

| 状态 | 必须做到 |
|---|---|
| 加载中 | 有可见反馈，不能转圈后什么也没发生 |
| 空 | 一句人话 + 一个下一步动作 |
| 错误 | 说清发生了什么 + 能做什么 |
| 离线 | 明示离线；动作给出原因 |
| 未连接 | 有连接入口 |
| 部分成功 | 报出真实的剩余数 |

三个「不知道」，说错即违约：

1. **未探测 ≠ 否**（能力没探测过 ≠ 不支持）。
2. **读不到 ≠ 不存在**（凭据解不开 ≠ 账号没保存）。
3. **没设过 ≠ 设成了 0**（预算没填 ≠ 上限是 0）。

源码位置：`web/src/core/errors.ts`（错误码字典）、`web/src/core/empty.ts`（空态规则）、
`web/src/core/async.ts`（六态阶梯）。

## 八、「成熟」的判据（终审用）

一个不是 demo、不是 hackathon 项目的产品，在**不知情的人**手里应该表现为：

1. 打开有窗口，不卡死，不报错，不显示内部变量名。
2. 每个按钮按下去都有可见的结果，包括失败。
3. 界面上没有一句话是假的。
4. 关掉再开，状态还在。
5. 出错时用户知道自己该做什么。
6. 拿给别人看，说得出它是什么、为什么这样设计。

**六条全中 = V1.0 可交付。缺一条都还在 V0.9。**
