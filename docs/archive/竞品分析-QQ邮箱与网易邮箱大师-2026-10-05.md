# 竞品分析：QQ邮箱 & 网易邮箱大师

> 调研日期：2026-10-05
> 调研范围：网页版 + 桌面客户端（两者交互差异明显，分开记录）
> 调研目的：为 Lagoon 补齐「废纸篓管理」「归档恢复」等管理类功能提供设计参照

---

## ⚠️ 首要结论：Lagoon 的「归档」不是竞品的「归档」

这是本次调研最重要的发现，**它推翻了我们对竞品归档功能的默认理解**：

| 产品 | 真实语义 | 实现方式 |
|---|---|---|
| Gmail | **移出收件箱，不删除** | 移除 `\Inbox` 标签，邮件**留在 All Mail** |
| QQ邮箱 | **真的移进"已归档"文件夹** | IMAP MOVE 到归档文件夹 |
| 网易邮箱 | **没有归档功能** | — |

**这意味着**：QQ邮箱的归档和 Lagoon 一样是**物理移动**（邮件离开收件箱，进入另一个文件夹）。所以 Lagoon 当前的实现（`provider.unarchive` 真实 IMAP MOVE）**与 QQ邮箱一致**，不是设计错误。

而 Gmail 那种"加标签式归档"** Lagoon 做不到也不该做**——它只同步 INBOX，没有 All Mail 概念。如果 Lagoon 学 Gmail 做"归档=移出收件箱"，用户会永远找不到那封邮件。

**对 Lagoon 的直接影响**：
- 归档必须有**恢复入口**（这是 QQ邮箱的必然要求，Lagoon 当前缺失）
- 废纸篓必须有**恢复入口**（Gmail/QQ 都有）
- 不要试图模仿 Gmail 的"All Mail"

## 一、QQ邮箱

### 1.1 废纸篓

| 能力 | 网页版 | 桌面客户端 |
|---|---|---|
| 列表展示 | ✅ | ✅ |
| 单封恢复 | ✅ | ✅ |
| **清空废纸篓** | ✅ | ✅ |
| 彻底删除（EXPUNGE） | 靠服务端策略 | 靠服务端策略 |

**关键交互**：
- 恢复按钮在列表顶部工具栏，**不在单封邮件的行内**
- 「清空废纸篓」在顶部，红色/危险色
- **⚠️ 待确认**：清空是否需要二次确认，确认弹窗文案具体措辞未查清
- 废纸篓邮件**不可回复**（收不到地址）

**可直接借鉴**：
1. 清空废纸篓放在**列表页顶部工具栏**，不是行内——因为这是"对这个列表"的操作，不是对某封邮件的操作
2. 危险色（红）+ 与"删除"视觉区分

### 1.2 归档

- 归档文件夹是**真实 IMAP 文件夹**（QQ 邮箱 2013 年前后上线该功能）
- 归档后邮件**离开收件箱计数**
- 归档邮件在"已归档"文件夹可见
- **⚠️ 待确认**：取消归档的入口具体位置（行内按钮 / 右键菜单 / 详情页按钮）未完全查清

**可直接借鉴**：
1. 归档 = 物理移动到独立文件夹（**Lagoon 已经是这样做的，正确**）
2. 归档文件夹要有独立入口（Lagoon 侧边栏已有「已归档」）

### 1.3 批量操作

- 列表顶部有全选复选框
- 选中后顶部出现操作工具栏
- **⚠️ 待确认**：是否有"全选所有 N 封（仅加载 M 封）"这种模式未查清

### 1.4 其他

- 标签体系：有（用户自建标签）
- 已发送：独立文件夹
- 草稿：独立文件夹
- 快捷键：网页版支持 `E` 归档等 Gmail 风格键位（**⚠️ 待确认**）

## 二、网易邮箱大师

### 2.1 废纸篓

| 能力 | 网页版 | 桌面客户端 |
|---|---|---|
| 列表展示 | ✅ | ✅ |
| 单封恢复 | ✅ | ✅ |
| 清空废纸篓 | ✅ | ✅ |
| 彻底删除 | ✅ | ✅ |

**关键交互**：
- 「彻底删除」是**显式按钮**，与「删除」（移入废纸篓）**明确区分**
- 彻底删除弹**二次确认**，强调不可恢复
- 恢复后邮件**回到收件箱**（不是原文件夹）

**可直接借鉴**：
1. **「删除」和「彻底删除」用两个不同措辞的按钮**，而不是同一个按钮的二次状态
2. 彻底删除的确认文案必须强调**不可恢复**
3. 网易的"恢复回到收件箱"是唯一合理语义（Lagoon 的 `restoreFromTrash` 已经是这个行为，正确）

### 2.2 归档

**⚠️ 重要：网易邮箱没有归档功能。** 这是本次调研确认的"不存在"信息，同样有价值——说明"归档 + 恢复"不是所有产品都做的，QQ邮箱做了是因为它有文件夹体系。

### 2.3 批量操作

- 桌面客户端支持全选 + 批量删除/移动/标记
- 批量删除有确认弹窗

### 2.4 其他

- 标签体系：有
- 已发送/草稿/垃圾箱：独立文件夹
- 桌面客户端有**本地邮件缓存**，离线可读

## 四、可直接照搬的交互细节（给 Lagoon）

### 4.1 立即可做（高价值、低成本）

1. **清空废纸篓放在列表顶部工具栏**，红色危险色，与单封删除视觉区分
   - 依据：QQ邮箱 + 网易都有，且都放在"对这个列表"的位置
   - Lagoon 实现：`Sidebar` 已有废纸篓入口，补一个顶部按钮即可

2. **「删除」与「彻底删除」用不同措辞的两个按钮**
   - 依据：网易邮箱大师
   - 关键：不要做成同一个按钮的"二次状态"，用户要能一眼看出区别

3. **恢复按钮放在详情页，不只放列表行内**
   - 依据：Gmail/QQ/网易都有详情页恢复
   - Lagoon 现状：只有行内右键，且没有恢复

4. **取消归档在详情页也要有**
   - 依据：QQ邮箱
   - Lagoon 现状：完全没有

5. **全选复选框在列表顶部**
   - 依据：四个产品都有
   - Lagoon 现状：完全无全选

### 4.2 需要设计决策

6. **彻底删除的确认强度**
   - Gmail 靠 30 天自动清理 + 清空时一次确认
   - 网易靠二次确认弹窗
   - **Lagoon 宪法 §2 要求所有变更可撤销，永久删除天然违反**
   - 建议：做，但 UI 明确标注不可撤销，依赖二次确认（与网易一致）

7. **废纸篓邮件能否预览**
   - 网易桌面端可以（本地缓存）
   - Gmail 网页版可以
   - Lagoon 当前：废纸篓邮件能打开详情（`MessageDetailView` 不区分状态）
   - **建议保持能预览**——用户需要确认"是不是我要恢复的那封"

### 4.3 明确不要抄

8. **不要抄 Gmail 的"归档 = 移出收件箱"**
   - 原因：Lagoon 只同步 INBOX，没有 All Mail，那样做邮件会永久失联
   - Lagoon 当前的文件夹式归档是对的，与 QQ邮箱一致

9. **不要抄网易的"没有归档"**
   - 邮箱体量决定，网易没有是因为它不做这个功能，不代表这是好设计
