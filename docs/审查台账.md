## §A 死链与假控件（用户已决策）

- **决策（用户，2026-10-21）**：**暂时移除死链，界面不留假按钮**。
- **事实**：`LagoonHelp.supportAddress` = `feedback@lagoon.email`（未替换的脱敏占位符）；
  `LagoonHelp.siteURL` = `https://lagoon.email`（未注册域名）。
  二者都是**死链**：About 页「发送反馈」+ 8 处横幅「帮助」按钮点了没有任何反应。
- **修法**：
  1. 删除 `supportAddress` 的占位符值 —— 改为"未配置"状态，`feedbackMailto` / `bannerMailto` 返回 `nil`。
  2. 所有调用点（`AboutSheet` + 8 处 `bannerMailto`）在 `nil` 时**不渲染按钮**，
     而不是渲染一个点了没反应的按钮。
  3. `siteURL` 同理：要么移除入口，要么只在有真实域名时显示。
  4. 加守卫测试：断言**产品里不存在任何指向占位符/未注册域名的可点击链接**。

## §I 编译警告闸门（当前基线红）

- **基线（2026-10-21）**：`swift build` 通过，但 `scripts/warn-gate.sh` 报 **14 个未批准警告**：
  - `Sources/Lagoon/Views/RootView.swift:973` — main actor 隔离方法跨 actor 调用（**Swift 6 下是错误**）
  - `Sources/LagoonServer/Routes/ActionsRoutes.swift:2018` — `insertOverride` 返回值未使用
  - `Tests/LagoonServerTests/DraftSealTests.swift` × 12 — `await` 无 async 操作 / 未使用变量
- **要求**：本轮结束前闸门必须绿。
- **状态（2026-10-21，已修）**：闸门已绿。14 条按根因分三类修：
  1. `RootView.swift:973` —— `reconnect()` 是 main actor 隔离方法，而 `action` 是
     `(@Sendable () async -> Void)`，跨 actor 调用必须 `await`。改为
     `await self.reconnect()`，与同文件 `healthNeedsReconnect` / `healthDegraded` 两处
     既有写法一致（那两处本来就带 `await`）。**这条是 Swift 6 下的真错误**，
     不是噪音。
  2. `ActionsRoutes.swift:2018` —— `insertOverride` 返回新行 id，此处显式 `_ =` 丢弃。
     查证：全仓仅此一处调用该 async 版本，且 counter-row 靠**更新**取胜而非靠 id 寻址；
     撤销是终态（`.undo` 不可再撤销），没有第二轮需要指向这行。故丢弃是安全的，
     非漏用返回值。
  3. `DraftSealTests.swift` × 12 —— `LagoonDB.read` / `.write` 是**同步** API
     （`LagoonKit/LagoonDB.swift:37,44`），11 处 `await` 是多余的；同文件里
     `legacy.write` / `reopened.write` 走的是 GRDB `DatabasePool`（真 async），
     其 `await` 保留不动。第 12 条是 `secret` 变量未使用——插入语句里写的是
     重复字面量，改为用 `secret` 本身，让"测试点名的字符串"就是"真正写进去的字符串"。
- **验证**：三条修复均做过**变异验证**（改坏 → 闸门/测试变红 → 逐字还原）：
  去掉 `await` 复现 1 条、去掉 `_ =` 复现 1 条、恢复 11 处 `await` 复现 11 条；
  行为层把"无密钥时丢弃草稿"改成保留，`DraftSealTests` 变红 1 条 —— 证明
  该测试真的在断言，没有因改动变成空转。`scripts/run-all-tests.sh` 全绿
  （闸门 0 警告，1419 个测试）。
