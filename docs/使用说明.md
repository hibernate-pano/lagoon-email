# Lagoon 使用说明（M0 阶段）

> 这份文档告诉你：从零开始，把 Lagoon 的「Gmail 同步 → 服务器 → macOS 客户端」全链路跑起来，需要做什么、每一步会发生什么、出错了怎么排查。
>
> 当前是 **M0 Spike**（架构验证阶段）：能连你的 Gmail、把最近 50 封邮件显示在 macOS 客户端里。Briefing Feed、AI 摘要、自动起草等 M1 起才有。

---

## 一、你需要准备什么

| 工具 | 用途 | 检查方法 |
|------|------|----------|
| Xcode 26+（含 Swift 工具链） | 编译全部代码 | `swift --version` |
| Docker（OrbStack 或 Docker Desktop） | 跑 Postgres 数据库 | `docker --version` |
| 终端 | 执行命令 | — |
| 一个 Gmail 账号 | 授权同步 | — |

不需要装本地 Postgres——我们用 Docker 容器跑数据库。**注意：如果你的电脑上已经有 Homebrew 的 postgresql 服务在 5432 端口跑着（`brew services list` 可以看），不要关它**，Lagoon 会用 5433 端口，两边互不干扰（配置已经写好了）。

## 二、五步跑起来

### 第 1 步：启动数据库

```bash
cd /Users/panbo/Code/Demos/lagoon-email
docker compose up -d
```

- 这会启动一个 Postgres 16 容器（带 pgvector 扩展），映射到本机 **5433** 端口。
- 验证：`docker ps` 能看到 `lagoon-postgres` 且状态为 Up。

### 第 2 步：创建环境配置

```bash
cp .env.example .env
```

然后编辑 `.env`，**暂时只需要关心两行**（第 3 步会拿到它们）：

```
GMAIL_OAUTH_CLIENT_ID=（稍后填）
GMAIL_OAUTH_CLIENT_SECRET=（稍后填）
```

`.env` 已经被 gitignore，里面的密钥**永远不会**被提交进仓库——这是工程约定（spec §6.6 规则 4）。

### 第 3 步：申请 Google OAuth 凭证（一次性，约 10 分钟）

这一步是整个流程里唯一需要你在浏览器里操作的环节。

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，登录你的 Gmail 账号
2. 顶部项目选择器 → **新建项目**，名字随便填（比如 `lagoon-dev`）
3. 左侧菜单 → **API 和服务 → 已启用的 API 和服务** → **+ 启用 API 和服务** → 搜索 **Gmail API** → 启用
4. 左侧 **OAuth 同意屏幕**：
   - User Type 选 **外部** → 创建
   - App name 填 `Lagoon`，用户支持电子邮件填你自己
   - 一路保存到底（其他都可以留空）
   - 回到同意屏幕页面 → **Audience（受众）** → **Test users（测试用户）** → **+ Add users** → **把你自己的 Gmail 加进去**（⚠️ 不加这步，后面授权会报 "access blocked"）
5. 左侧 **凭据（Credentials）** → **+ 创建凭据 → OAuth 客户端 ID**：
   - 应用类型：**Web 应用**
   - 名称：`lagoon-local`
   - **已获授权的重定向 URI**（必须一字不差）：
     ```
     http://127.0.0.1:8080/oauth/gmail/callback
     ```
   - 创建后会弹出一个窗口，里面有 **客户端 ID** 和 **客户端密钥**
6. 把这两个值填进 `.env`：

```
GMAIL_OAUTH_CLIENT_ID=1234-abc.apps.googleusercontent.com
GMAIL_OAUTH_CLIENT_SECRET=GOCSPX-xxxxxxxx
```

> 新建的 OAuth client 通常需要 5 分钟到几小时才生效。如果第一次授权报 `invalid_client`，等几分钟再试。

### 第 4 步：建表 + 编译 + 全量自检

```bash
bash scripts/run-all-tests.sh
```

这个脚本依次做四件事：安全守卫检查（SQL 参数化、密钥泄漏扫描）→ 数据库迁移（幂等，重复跑不会坏）→ 跑全部测试 → 编译服务器和客户端。看到最后一行 `ALL CHECKS PASSED` 就说明环境完全就绪。

### 第 5 步：启动服务端和客户端

开两个终端窗口：

**终端 1 —— 服务器：**

```bash
set -a; source .env; set +a
export DATABASE_URL=postgres://lagoon:lagoon@127.0.0.1:5433/lagoon
swift run LagoonServer
```

看到 `Server started and listening on 127.0.0.1:8080` 即成功。

**终端 2 —— macOS 客户端：**

```bash
swift run Lagoon
```

会弹出 Lagoon 窗口 → 点 **Connect Gmail** → 浏览器打开 Google 授权页 → 选择你的账号 → 同意（可能会提示"未经验证"，点"继续"即可，因为你自己就是测试用户）→ 回到 Lagoon 窗口。

此时客户端会自动调 `/api/messages`，**你最近 50 封 Gmail 邮件**（发件人、主题、时间、摘要）就会出现在列表里。服务器每 30 秒轮询一次新邮件。

> 想从零再连一次：客户端菜单/界面暂无「断开」按钮，跑 `defaults` 不行的话直接清 Keychain 即可——在终端执行：
> ```bash
> security delete-generic-password -s lagoon.accountId 2>/dev/null; echo done
> ```
> 然后重启客户端就会回到 Connect 页面。

| 能 ✅ | 不能 ❌（按计划属于 M1+） |
|------|------|
| Gmail OAuth 授权登录 | Token 过期自动刷新（过期后需重新 Connect） |

| 30 秒自动轮询新邮件 | Google Pub/Sub 实时推送（现在是轮询替身） |
| 邮件数据落在本地 Docker Postgres | Briefing Feed、AI 摘要、智能分堆 |
| AI 自动整理 / 起草 / 自动归档 | （M1 起逐步交付，模型已定为 MiniMax-M3） |

## 四、常见问题排查

**1. 授权页报 `Error 403: access_denied` / 「应用未经过验证」**
→ 第 3 步第 4 小项漏了：把你自己的 Gmail 加进 OAuth 同意屏幕的 **测试用户** 列表。

**2. 授权页报 `Error 400: redirect_uri_mismatch`**
→ Google Cloud 里配置的重定向 URI 和实际不一致。必须是精确的 `http://127.0.0.1:8080/oauth/gmail/callback`（不是 localhost，不是 https，尾部无斜杠）。

**3. 客户端显示 "Sync failed: …"，或者列表为空**
→ 先确认服务器在跑：`curl http://127.0.0.1:8080/healthz` 应返回 `ok`。
→ 如果服务器日志里出现 `token expired`：access token 约 1 小时过期，M0 不做自动刷新，重新点 Connect Gmail 即可。
→ 数据库没起：`docker compose up -d`。

**4. 端口 5432 / 5433 被占用？**
→ 本机已有 postgres 占 5432 是**正常**的，Lagoon 用 5433。如果 5433 也被占，改 `docker-compose.yml` 里的映射（如 `5434:5432`）和 `.env` 里的 `DATABASE_URL`，两处保持一致。

**4b. 服务器访问 Google 超时 / TLS 报错（-1200 / -1001 / -1005）？**
→ 取决于你的网络能否直连 Google。服务器只看一个环境变量 `LAGOON_HTTP_PROXY`：
- 国内网络（直连被墙）：`.env` 里设 `LAGOON_HTTP_PROXY=http://127.0.0.1:7897`（换成你代理软件的 HTTP 端口），重启服务器
- 直连可达（或 Clash 开了 TUN 模式）：留空即可，服务器会绕过系统代理直连
出站目标有 host 白名单（只允许 Google OAuth/Gmail 域名，https only），代理只影响连通性、不影响安全边界。

**4c. Google 授权页显示的应用名不是 "Lagoon"？**
→ 授权页的名字来自 Google Cloud 里 **OAuth 同意屏幕** 的 App name，跟 `.env` 里 client ID 所属的项目绑定。常见原因：OAuth client 建在了另一个（旧）项目里，或改名后还没传播（几分钟延迟）。处理：确认 `.env` 的 client ID 来自哪个项目（Credentials 页面能看到），在该项目的「OAuth 同意屏幕」里把 App name 改成 Lagoon，保存后等几分钟重新授权。名字只是展示，不影响功能与安全（授权用 PKCE + state 校验）。

**5. `swift build` 报错 / 测试失败**
→ 先跑 `bash scripts/run-all-tests.sh` 拿到完整报错，对照 `docs/superpowers/m0-smoke.md` 的「已知偏差」部分——PostgresNIO 版本和 macOS 26 SDK 的兼容性坑已经踩过并记录了。

**6. 想彻底重置数据库**
```bash
docker compose down -v   # -v 会删掉数据卷，邮件缓存全部清空
docker compose up -d
bash scripts/db-migrate.sh
```

## 五、日常开发命令速查

```bash
bash scripts/run-all-tests.sh   # 全量自检（守卫 + 迁移 + 测试 + 编译）
bash scripts/ci-guardrails.sh   # 只跑安全守卫（SQL 注入 / 密钥泄漏）
bash scripts/db-migrate.sh      # 应用新的数据库迁移
docker compose up -d            # 起数据库
docker compose down -v          # 彻底重置数据库（删数据）
```

## 六、代码在哪一层

```
Sources/LagoonKit      ← 两端共享的类型和数据库助手（改动需两端回归）
Sources/LagoonServer   ← Hummingbird 服务器：OAuth、Gmail 拉取、同步 API
Sources/Lagoon         ← macOS SwiftUI 客户端
Sources/LagoonKit/Migrations  ← 数据库表结构（改这里 + 重跑迁移脚本）
docs/superpowers/      ← 产品 spec、M0 计划、冒烟测试记录
```
