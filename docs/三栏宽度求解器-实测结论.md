## 一、实测环境

- 探针脚本：`/tmp/dragprobe/solver2.py`（water-filling 迭代版）
- 参数：3 栏，`min=[180,280,360]`、`max=[300,460,900]`、`weight=[1,2,3]`
- 窗口宽度扫描：1400 / 1000 / 820 / 819 / 760

## 二、四条硬结论

### 结论 1：朴素迭代法会溢出（实测 8/8 组异常）

拖动某栏时，若"触界栏"没有被正确冻结，迭代会算出**合计超过总宽**的解：

```
=== 总宽 1000 ===
  拖阅读器 -> 900:  [94.00, 94.00, 900.00]  合计=1088.00  目标=994.00  溢出 94pt
                                   ^^^^^^^^ 两栏都被击穿到min以下
```

**结论：不要用"反复迭代到不动点"的写法。** 迭代法的收敛性依赖
"哪些栏被冻结"的判断，而该判断在多栏钳制时会自相矛盾。
必须用**确定性直接解法**（见结论 4）。

### 结论 2：现有 `minWidth: 720` 与三栏下限互相矛盾（实测）

三栏下限之和 = `180 + 280 + 360 = 820`，但两条 surface 声明的是
`.frame(minWidth: 720, minHeight: 480)`（`MessageListView.swift:567`、
`BriefingFeedView.swift:163`）。

**720 < 820 → 数学上必然击穿下限。** 实测在总宽 760 时：

```
  拖列表 -> 460:  [180, 460, 294.00]  合计=934.00  目标=754.00
                                ^^^^^ 阅读器 294 < min 360，下限被击穿
```

**必须做的决策**（请在架构里明确）：
- 要么把三栏 `min` 下调，使 `sum(min) + 分隔线 ≤ 窗口下限`
- 要么把窗口 `minWidth` 上调到 `sum(min) + 分隔线`
- 要么引入"窄窗口降级策略"（如阅读器可低于 min，见结论 3）

**不能三者都不做** —— 那是把 bug 写进架构。

### 结论 3：空间不足时必须定义明确的"亏空语义"

实测在总宽 819（< 820）时，三栏 min 无法同时满足。求解器必须回答：
是让某一栏破下限（谁的优先级最低？），还是让窗口内容溢出被裁剪，
还是折叠某栏？**沉默地溢出或沉默地破界都是不可接受的。**

### 结论 4：迭代的最后一轮覆盖会吞掉已算结果（探针自身 bug，值得记）

第一版探针里写了 `res=new`，其中 `new` 是 dict，`sum(res)` 实际在求键之和，
导致"合计=3.00"这种荒谬结果。

**教训：这类求解器的测试必须断言"合计 == 目标总宽"这个不变量，
不能只断言各栏不越界。** 只断言不越界的话，上面四种失败全部能通过测试。

## 三、建议的直接解法（water-filling 的解析式，供参考）

不做迭代，而是**一次排序 + 一次扫描**：

1. 钳制被拖栏：`t = clamp(target, min[i], max[i])`
2. 剩余空间 `R = total - divider - t`
3. 对其余栏按 `weight` 排序（权重降序，或按"离界的远近"排序）
4. 单遍扫描：逐栏 `w_i = R * weight_i / sum(weight_active)`，
   钳制到 `[min_i, max_i]`；**被钳制的栏立刻退出活跃集，
   并把R 按权重重新分配给仍活跃的栏**（这是 water-filling 的核心，
   但只需单遍 + 一次性重分配，不需要反复迭代）
5. 若仍有剩余（所有栏都到 max），把剩余平摊回各栏（或给弹性最大的栏）
6. 若仍不足（所有栏都到 min），按**明确声明的优先级**依次突破下限

复杂度 O(n log n)，n=3 时是一次排序，无需循环。

## 四、必须写成测试的不变量

QA 请把以下每一条都做成测试用例（不是"顺手测一下"，是**断言**）：

1. `sum(widths) + divider == total`（容差 < 0.5pt）
2. 每个 `width ∈ [effectiveMin, effectiveMax]`
3. 宽度非负
4. 同一输入重复求解结果完全一致（**确定性**）
5. 窗口宽度单调变化时，不应出现某栏宽度**跳变**（连续性）
6. 拖到极值时结果等于该栏的 `min` 或 `max`（钳制生效）
7. 空间不足（total < sum(min)）时的行为**符合明确定义的语义**，不是溢出
