# R1 轮次记录：已发送列表

> 2026-10-05 · 迭代路线第 1 轮
> 起点 777 测试 → 终点 **794 测试**（+17），四道闸门全绿

---

## 一、这轮做完了什么

**功能**：侧边栏「位置」分组新增「已发送」，可浏览、可搜索、可进详情、可批量操作。

但真正的发现比功能本身重要。

### 已发送邮件从未进过本地库

`IMAPProvider.collectSentReplies` 的注释直说：

> Sent mail is never stored as rows — only the threading references are returned.

同步循环 `select(inboxName)`，只拉 INBOX。发信时确实 `APPEND` 到服务器 Sent 文件夹，但那份数据**从未同步到本地**。所以这不是"加个 UI 入口"的活儿，需要一条全新的数据通路。

### 为什么是独立路由而不是 `?sent=true`

| 决定 | 理由 |
|---|---|
| 独立 `/api/sent` | `/api/messages` 每 30 秒轮询，加分支等于每次收件轮询都带一个没人走到的条件 |
| 同上 | **Sent 是唯一需要在入口读 provider 的轴**。收件/归档/废纸篓都能从本地表答，Sent 不能——本地表根本不知道它 |
| `listSent` **无 cursor** | 有 cursor 就意味着 reconcile。reconcile Sent 文件夹会删掉用户在别的客户端能看到的邮件，这正是本项目已付过一次学费的 bug 类型 |

**代价是两次 IMAP 会话**，所以客户端超时用了 `slow` 而非 `fast`。

### 数据落库带来的是复利

`refresh` 走的是**和收件箱同步一模一样的** `MessageStore.upsert`。所以一次已发送拉取之后，搜索、线程跳转、详情页、批量操作**全部自动支持已发送邮件**，没有一行额外代码。

只有 `is_sent` 标记是单独写的——原因见下。

## 二、两个必须记住的不变量

### ① `upsert` 绝不写 `is_sent`

`is_sent` 来自**从哪个文件夹同步**，不是邮件本身的任何字段。

如果让 `upsert` 写它：我发出的回复（`From:` 是我自己的地址）会在**下次收件箱同步时**把自己翻成「已发送」，从收件箱消失。这是最隐蔽的一种错——没有任何报错，只是邮件不见了。

测试：`test_upsertDoesNotSetTheSentFlag`

### ② 三轴互斥

`is_sent` 是第三个独立轴（继 `is_archived`、`is_deleted` 之后）。**收件箱、档案柜、所有聚合规则列表一律 `is_sent = FALSE`。**

`test_theThreeAxesAreMutuallyExclusive` 穷举 8 种 (sent, archived, deleted) 组合，每种断言**恰好出现在 1 个列表**。

这条测试的来历：之前「先归档后删除」的邮件**在两个列表里都不出现**（一个查 `is_archived=FALSE`、一个查 `is_deleted=FALSE`，两把扫帚都把它扫出去了）。加上第三个轴时，同一个 bug 有三个可能的位置。

## 三、这轮抓到的三个真 bug

### 1. 已发送邮件泄漏进收件箱

`filterSQL` 里我只在 `sent=true` 时加了条件，忘了给其他分支加 `is_sent = FALSE`。8 组合测试立刻抓到：`out appears in 2 lists, expected 1`。

### 2. 工具栏标题硬编码 —— 三个界面都写着「全部邮件」

```swift
Text(l10n.allMessages)   // ← 废纸篓、档案柜、已发送，全都显示这个
```

这和之前修的 `case .deleted: self = .all` 是**同一类错误**：界面说一件事、内容是另一件事。而工具栏标题恰恰是用户唯一用来确认"我在哪"的地方。

现在标题跟随透镜，`test_everyFolderLensHasItsOwnTitle` 锁住。

### 3. 未读 / 置顶徽章计数泄漏（轮末体检发现，不是测试）

`unreadCount` 和 `pinnedCount` **早于 `filterSQL` 存在，自己手写谓词**。给共享 clause 加第三个轴时，静默跳过了它们。

后果：一封我发出但没标记已读的回复，会挂在**未读徽章**上，却不在**任何列表**里——徽章的数字和它标注的列表对不上。

这个只有轮末体检能发现，因为它不在本轮新增的代码路径上，而在**本轮改动波及的旧代码**上。

## 四、UI / 交互复核

### 空状态按透镜分化

原来一句 `l10n.noMessagesYet`（「还没有邮件」）用在所有透镜上。在废纸篓里它说"邮件不见了"，而实际上什么都没删过。

现在每个透镜有自己的图标 + 标题 + 提示。已发送的提示是「从 Lagoon 发出的邮件会自动出现在这里」——因为那个空状态最容易被误读成功能坏了。

### 「可能不是最新」而不是报错页

服务器拉不到时，**仍然渲染已存的行**，顶部加一条橙色细条。

理由：用户打开已发送是为了读一封旧回复，不是检查网络。报错页是更差的答案。而且这不是用户能采取行动的错误，所以刻意不放进 `errorBanner`，单独用 `isSentStale`。

### 404 而不是空列表

「这个账户没有已发送文件夹」和「你从没发过邮件」是两句不同的话。只有第一句为真时不能显示第二句——那是个小谎，代价是用户不再信任这个界面。

### 已发送徽章是下界，且为 optional

`FolderCounts.sent` 只数本地已知的，即"打开过已发送之后"才知道。这是诚实的答案。

字段设计成 `Int?` 而非 `Int`：旧载荷解码为 `nil`（客户端不显示徽章）而不是 `0`（声称"你什么都没发过"）。测试 `test_sentCount_isOptional_soLegacyPayloadsDoNotClaimZero`。

## 五、这轮我自己犯的错（同步记录）

1. **Python heredoc 里嵌 Swift 三引号 SQL** → `IndentationError: unexpected indent`。三次。改用 Edit 工具写 SQL。
2. **测试元组标签写成 `sent` 却按 `rows` 取** —— 编译错误。
3. **`message_pins` 列名是 `created_at` 不是 `pinned_at`** —— 凭印象写的。
4. **`seedLocal` 建的是已读**，未读测试的控制行必须显式设未读，否则测试通过但没测到东西。
5. **一度想给 `SyncRoutes` 加 `?sent=true`** —— 写到一半发现它没有 `makeProvider`，而且会污染热路径。回退，改为独立路由。
6. **写了 `accounts.setLastSync(resp) if false else ()`** 这种废码（`resp` 在那个分支根本不存在）。编译通过是因为它在 `if false` 分支里。
