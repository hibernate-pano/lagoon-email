## 一、执行摘要

代码质量在**状态机与竞态**层面相当高：两段式全选、RefreshGate、乐观回滚、批量 undo、密度共享、列宽求解器都做得很扎实，注释也解释「为什么」而非「是什么」。**本报告的问题几乎全部在「表层」**——也就是用户第一眼看见的东西。

三个结构性的根因：

1. **设计系统只有一个颜色，且三个里的两个从未被使用。** `LagoonTheme` 定义了 `brand` / `deepTeal` / `accent` 三个色，但全仓库只有 **1 处**引用（`LagoonApp.swift:51` 的 `.tint(LagoonTheme.brand)`）。`deepTeal` 的注释白纸黑字写着"用于消息列表的未读指示点"，而未读点实际用的是 `.fill(.tint)`。结果是**界面上的"系统蓝"和"Lagoon 青"同时存在**，四个滑动操作（`.tint(.blue)` / `.tint(.orange)` / `.tint(.yellow)` / `.tint(.green)`）完全绕开了品牌色。这是"看起来像 hackathon demo"的第一大来源。

2. **三个邮件表面各自长出了自己的排版。** 简报行、原始列表行、会话行、搜索结果行、发件人排行行、悬停卡——六种"邮件行"，字号/间距/截断规则各不相同。**同一个"邮件行"概念，六套实现**。用户从简报切到全部邮件时，视觉上像换了一个 app。

3. **错误提示的"具体度"没有统一标准。** 项目自己的规范（`docs/superpowers/specs/2026-09-13-client-ux-feedback-discipline.md` INV-3）写着「`detail` 不可为空，必须说明『什么失败』+『为什么』」，但代码里有 **14 处 `.error` banner 没有 detail**，其中 4 处是**可重试**错误（违反 INV-4：可重试错误必须带 retry 按钮）。规范存在，落地不齐。

**问题总数：53 条**（P0 = 2、P1 = 18、P2 = 20、P2 = 13）。最高价值的三条：
- **UX-01** 未读圆点只靠颜色 + 2pt 尺寸传达状态，且尺寸有 6/7/8 三种（无障碍 P0）
- **UX-05** 简报的置顶邮件在原始列表里**没有任何视觉标记**（功能可见性 P0）
- **UX-58** `AdviceSheet` 的"忽略建议失败"错误**永远不会显示**（静默失败，P1）

## 三、视觉 / 文案层面最影响专业感的 10 个点

> 这是交付质量的门面。按「用户第一眼看见」和「截图给人看」的影响排序。

### ① 未读圆点只靠 7pt + 颜色 —— 深色模式下基本消失
`MessageListView.swift:1060-1068`。全屏唯一的"这是什么级别的重要"信号是一个 7pt 的青色圆点。深色模式里 `.tint` 落在深色行底上，对比度接近 2:1，**截图给投资人看时，未读邮件和已读邮件长得一模一样**。改成左侧 2pt accent 竖条 + 圆点，密度不变但可读性翻倍。（对应 UX-01）

### ② 两个表面两套行排版，一眼能看出不是同一个产品
简报行 subject `.body` / spacing 4 / snippet `.caption2`+secondary（`BriefingFeedView.swift:1208-1236`）；原始列表行 subject `.body` / spacing 2 / snippet `.caption2` **无 secondary**（`MessageListView.swift:1094-1117`）。**最后那个 `secondary` 的缺失是肉眼可见的深浅不一**。而且原始列表行首是 7pt 圆点、简报行首是 28pt 头像——用户视线在两列之间来回时会跳。（对应 UX-15、UX-18）

### ③ 「已归档」被当成按钮标签用
`L10n.swift:500` 一个字符串同时当**完成态**（toast）和**动作**（按钮 / 滑动 / 右键）。用户右键看到「已归档」，那是一个完成时态的词，不是动词。**这是全 app 最刺眼的一处文案不一致**。（对应 UX-21）

### ④ 品牌色定义了三个，只用了一个
`LagoonTheme.swift:15-25`。`deepTeal` 的注释写着"用于消息列表的未读指示点"，但未读点用的是 `.tint`；`accent` 的注释写着"用于破坏性归档动作"，但归档滑动用的是 `.tint(.orange)`。**四个滑动操作全部是系统色**（蓝 / 绿 / 橙 / 黄），和窗口标题栏的青色调完全不搭。（对应 UX-02）

### ⑤ 简报里置顶的邮件，在全部邮件里找不到
`MessageListView.swift:1058-1118` 从不读 `isPinned`。用户在简报看到"已置顶"分组有 12 封，切到全部邮件**一封都定位不到**。这是**功能承诺与实现的裂缝**，不是美观问题。（对应 UX-05）

### ⑥ 成功提示是蓝色的（看起来像报错）
规范 §2.5 要求成功用绿色左边条的 `SuccessNotice`，代码里**没有这个类型**——所有成功（"已发送"、"同步已恢复"、"已彻底删除 N 封"）都走 `ErrorBanner(severity: .info)`，渲染成**蓝色 `info.circle.fill`**。（对应 UX-48）

### ⑦ 错误横幅固定 36pt，长 detail 被裁
`NoticeBanner.swift:102` + `:60-69`。banner 是「标题 + detail」两行，却塞进 36pt 固定高度——**detail 必然被截断**。而 INV-3 要求 detail 必须说明「为什么」。规范本身自相矛盾。（对应 UX-46）

### ⑧ 置顶失败没有重试按钮，同文件的标已读失败却有
`MessageListView.swift:1426`（置顶失败，**无 retry**）vs `:1393-1399`（标已读失败，**有 retry**）。同一个文件、同一种乐观回滚模式，错误处理不一致。（对应 UX-44）

### ⑨ 悬浮卡 / 弹窗尺寸没有规律
360 / 420 / 460 / 480 / 520 / 560 / 620 / 640 —— **八种宽度**、六种高度。两个 sheet 并排打开时宽度不同，是"业余软件"最直接的信号。（对应 UX-04）

### ⑩ 快捷键速查表里的 ⌘0 说明是假的
速查表写「在简报和全部邮件之间切换」（`ShortcutsSheet.swift:29`），代码里简报的 ⌘0 是"去全部邮件"、列表的 ⌘0 是"去简报"——**描述对了但描述的是 toggle，而代码是"跳到另一个"**（虽然结果一样，但 ⌘K 面板声明它是 toggle）。更严重的是速查表**没说哪些键只在哪个表面有效**：简报里的 j/k、⌘1–9，列表里的 ⌫/⌘⌫，切到另一个表面按下去毫无反应且零解释。（对应 UX-30、UX-34）

### ⑪ 隐藏 surface 的快捷键没门控 —— 这个坑本项目自己记过，又踩了一次
`.memory/toolbar-items-escape-hidden-zstack-surfaces.md` 明确把「keyboard shortcut（background Button 兜底那种）」列进旁路清单，当时的修法是给详情页加 `surfaceVisible` 门控。**现在 `surfaceVisible` 全仓库零命中**——详情页改成常驻 actionBar 时门控一并没了。两个常驻 surface 各有一个 `MessageDetailView` 实例，**⌘R / ⌘E / ⌘P / ⌘D 全部同时注册**。用户在简报面按 ⌘R，可能打开看不见的那个详情页的回复框。**同一个洞开了两次**。（对应 UX-63、UX-64）

### ⑫ 速查表教的两个键（⌘B / ⇧⌘A）按了没反应
它们绑在工具栏 ⋯ 菜单**内部**的 Button 上——macOS 的 `Menu` 内快捷键只在菜单打开时生效。速查表把它们当全局键教，用户按了**什么都不会发生**。而 ⌘K 放在 `.background` 里是真全局的——**同一个窗口里两种快捷键实现方式，用户学到的规律是"不可靠"**。（对应 UX-62）

## 四、设计 token 收敛建议

### 现状（实测）

| 类别 | 数量 | 备注 |
|---|---|---|
| `.font()` 总调用 | **202** | 198 个是语义 SF 字体（可缩放 ✅），**只有 3 个硬编码 `.system(size:)`** |
| `.foregroundStyle()` 总调用 | **178** | 162 个是系统语义色；**16 个是具名颜色字面量**（`.red`/`.green`/`.orange`/`.blue`/`.yellow`） |
| `.tint()` | **4** | **全部绕过品牌色** |
| `.padding()` | **108** | 17 个不同值 |
| `spacing:` | **130** | 11 个不同值 |
| `.frame(数字)` | **96** | 64 个含数字实参 |
| `cornerRadius:` | **11** | 3 个不同值（4/6/8） |
| `.lineLimit(N)` | **37** | 3 个不同值（1/2/3） |
| **设计数值字面量合计** | **≈ 387 处** | **去重后 45 个不同数值** |

**重灾区**（按硬编码设计数值综合计数）：`MessageListView.swift` 48 → `MessageDetailView.swift` 33 → `BriefingFeedView.swift` 25 → `StackSheets.swift` 24 → `SenderSheet.swift` 21 → `SenderRankingSheet.swift` 21。

**正面样板**：`Views/ColumnLayout/` 的 5 个文件**零硬编码**——所有几何量集中在 `ColumnLayoutMetrics`（`LagoonColumn.swift:57-123`）。**这次收敛应该照抄这个模式。**

### 建议收敛为 4 个 token 文件 / 约 60 个 token

```
Sources/Lagoon/Theme/
├── LagoonTheme.swift        （扩为语义色板，保留品牌三原色 + 严重级别色）
├── LagoonMetrics.swift      （间距 / 圆角 / 尺寸 / 行高）
├── LagoonTypography.swift   （字号语义 + 行文本排版规则）
└── LagoonSheetSize.swift    （弹窗尺寸阶梯）
```

**1. 颜色 —— 12 个 token**（从 16 处字面量 + 4 处 `.tint()` + 3 套色板）
```swift
enum LagoonTheme {
    // 品牌
    static let brand      = Color(red: 0.12, green: 0.43, blue: 0.52)  // #1F6F84 原 brand
    static let brandDeep  = Color(red: 0.05, green: 0.23, blue: 0.29)  // #0E3A4A 原 deepTeal
    static let brandAccent= Color(red: 0.91, green: 0.64, blue: 0.36)  // #E8A35C 原 accent
    // 严重级别（合并 NoticeBanner / RootView.statusColor / inlineNotice 三套色板）
    static let info      = .blue
    static let success   = .green
    static let warning   = .orange
    static let danger    = .red
    static let neutral   = .gray
    // 用法
    static func severityColor(_ s: Severity) -> Color
    static func severityIcon(_ s: Severity) -> String
}
```
**必须顺带解决的 4 处分歧**：状态圆点尺寸（6/7/8 → `LagoonMetrics.statusDotSize = 8`、`unreadDotSize = 7`）；`.quaternary` 透明度（0.3/0.35/0.5 → 统一 0.5 或按语义分两档）；chip 圆角（4/6/8 → 4 用于小 chip、6 用于输入框、8 用于卡片，**写进 token 而不是各写各的**）；严重级别色板。

**2. 间距 —— 8 档**（从 28 个不同值）
```swift
enum LagoonMetrics {
    static let spaceXS: CGFloat = 4     // 行内元素间距
    static let spaceSM: CGFloat = 8     // 控件之间
    static let spaceMD: CGFloat = 12    // 分组内
    static let spaceLG: CGFloat = 16    // 区块之间
    static let spaceXL: CGFloat = 24    // 页面内边距
    static let spaceXXL: CGFloat = 32
    static let radiusSmall: CGFloat = 4
    static let radiusMedium: CGFloat = 8
    static let statusDotSize: CGFloat = 8
    static let unreadDotSize: CGFloat = 7
    static let avatarSize: CGFloat = 28
    static let readingColumnWidth: CGFloat = 900
}
```
**顺带统一 4 组分歧**：「加载/空状态 padding」20 vs 30 → 统一 24；「关闭按钮 padding」11 处 `.padding(4)` 但 `CommandPaletteView.swift:120` 没有 → 统一；「弹窗宽度」8 种 → 3 档。

**3. 排版 —— 6 个行文本 token**（解决 UX-15 的六套行）
```swift
enum LagoonTypography {
    static let rowSubject: Font = .body
    static let rowSender: Font = .caption
    static let rowSnippet: Font = .caption2
    static let rowTime: Font = .caption2
    static let rowSpacing: CGFloat = 4
    static let rowSnippetLines = 2
}
```
**顺带统一**：简报与原始列表的时间格式（UX-17）、snippet 的 `.secondary` 缺失（UX-15）、密集档的 subject 字号 `.body` vs `.callout`（UX-15）。

**4. 弹窗尺寸 —— 4 档**
```swift
enum LagoonSheetSize {
    static let compact = CGSize(width: 360, height: 360)   // About
    static let standard = CGSize(width: 520, height: 480)  // 多数
    static let wide = CGSize(width: 640, height: 560)      // Search / Sender
    static let composer = CGSize(width: 600, height: 520)  // Composer / NewMessage
}
```

**收敛后的目标**：**387 处字面量 → 约 60 个 token 引用点**，45 个不同数值 → 8（间距）+ 3（圆角）+ 3（字号族）+ 4（弹窗尺寸）+ 12（颜色）。

### 收敛优先级（按性价比）

1. **颜色**（改动最小、视觉影响最大）—— 16 处字面量 + 4 处 `.tint()` + 3 套色板合并成一套，顺手让 `deepTeal` / `accent` 真正被用上。
2. **行文本排版**（UX-15/17/18）—— 6 个 token 消灭 6 套行排版，是"看起来像一个产品"的最大单点收益。
3. **间距 8 档** —— 28 个不同值收敛，顺手修 4 组一致性分歧。
4. **弹窗尺寸 4 档** —— 8 种宽度 → 3 种。
5. **字号层不动** —— 98.5% 已是语义字体，只需处理 3 处 `.system(size:)`（UX-37）。

### 需要产品拍板的两条（本轮不改代码，留给决策）
