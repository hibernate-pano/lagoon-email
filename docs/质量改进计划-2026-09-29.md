日期：2026-09-29
基线：`ea4118b` (v3.0.0) + 6 个未提交的同步性能修复文件

## 0. 方法

对 6 个子系统各派一个只读审计 agent（IMAP / 路由与出网安全 / 存储与同步 / SwiftUI 客户端 / 构建与文档 / 测试质量），
再由我逐条复核高危项——**6 条被复核推翻**，未写进下面的清单：

| 被推翻的结论 | 实际情况 |
|---|---|
| 「CI 是红的，因为 `RouteTests.swift` 引用了 PostgresNIO，而 postgres-nio 是陈旧残留」中「陈旧残留所以失败」部分 | 残留确实存在，但真正的原因是 **`Package.resolved` 里根本没有 postgres-nio**，全新 checkout 拿不到该模块 |
| 「工作区承载未提交的 V2→V3 迁移」 | 迁移已在 `ea4118b` 提交，工作区只剩 6 个同步性能文件 |
| 「仓库没有 v3.0.0 tag」 | 有 |
| 「`UnsubscribeScannerTests` 的 `resolveOverride` 装上后从不重置，全靠测试类名字母序」 | `tearDown` 第 15-19 行确实重置为 nil |
| 「`.memory/` 未被 gitignore，两篇 Postgres 笔记会被误提交」 | 成立但优先级低，降级到 W6 |
| 「README/使用说明/启动说明 有过时的架构断言」 | 三份都是当前的，唯一过时的是 `docs/superpowers/` 归档 |

**排序标准**（对齐「每天开两次、10 分钟清零」的定位）：

1. 确定性 bug（每次都用必现）> 竞态 > 硬化
2. 静默失败 > 崩溃 > 报错
3. 破坏产品承诺（撤销、隐私、闭环）> 体验瑕疵
4. 会误导后续修改的脏东西（陈旧文档、死代码）优先级高于新增功能

## 1. 诊断结论：9 个编译警告里藏着 3 个真 bug

`swift build` 只警告不报错，所以下面三个缺陷从「测试全绿」里完整活了下来：

| # | 位置 | 真相 |
|---|---|---|
| 1 | `ActionsRoutes.swift:1113` | `urlSession(_:dataTask:didReceive:completionHandler:)` **不是** `URLSessionDataDelegate` 的任何方法签名。编译器原话："nearly matches optional requirement"。**响应体上限从未生效**——攻击者的 newsletter 可以让 Lagoon 无限缓冲。 |
| 2 | `MessageStore.swift:31` | `let merged` 算完就扔，第 62 行绑定的是**合并前**的 `linksJSON`。`ON CONFLICT` 又做 `unsubscribe_links = EXCLUDED.unsubscribe_links` → **每次同步都把已采集的退订链接清空**。 |
| 3 | `AIGateway.swift:409,426` | 在 `async` 函数里直接 `NSLock().lock()`。Swift 6 语言模式下这是**编译错误**。 |

**这个模式本身就是结论**：`run-all-tests.sh` 没有 `-warnings-as-errors`，于是「警告」这一级信号被整个丢弃。
W0 的最后一步就是把这个闸门装回去。

## 复审发现并当场修掉的自身缺陷

独立复审 agent 报了 8 条，其中 **1 条是误报**（说 `tr/SEARCH//` 会改写操作数 →
lint 恒不失败；实测 `tr/{//` 是只计数不替换的形式，fixture 证明它能报出 2 条）。
其余真问题已修：两个轮询器的 `isLoading` 在 generation 早退时永不复位（会永久冻结列表）、

warn-gate 会把依赖包的警告算进来。

## 沉淀下来的三条规则

1. **警告不是输出，是信号。** 本次 3 个真 bug 全都藏在「测试全绿」的警告里。
   `scripts/warn-gate.sh` 是为此存在的，装在 `run-all-tests.sh` 的测试**之前**。
2. **不能失败的守卫比没有守卫更糟。** `lint-no-silent-catch.sh` 原来是一行
   grep，对 47 处 `catch {` 报「✅ 无静默捕获」而一处都没看过。改写为括号匹配
   解析器，并在 `test-guardrails.sh` 里加了 4 条 fixture 自测（2 正 2 负）钉住它。
3. **会自己坏掉的守卫同样糟——而且更隐蔽（2026-10-02 补）。** 规则 2 只堵住了
   「永远绿」，漏掉了「永远红」。`warn-gate.sh` 恰恰是后者：它坏了一整天，
   把自己的 3 条豁免报成违规。而**永久红的门等于一扇被拆掉的门**，人只会绕过它。
   更值得记的是为什么没人发现：`ci-guardrails.sh` 和 `lint-no-silent-catch.sh`
   都有自测，唯独 warn-gate 没有——**越是被指望拦住漏洞的组件，越需要有一个
   证明它会失败的 fixture**。详见第三轮。

# 第三轮：闸门自己坏了（2026-10-02）

第一轮装好的 `warn-gate.sh`，**从装上那天起就是红的**，持续了一整天。
它把 allowlist 里自己批准的那 3 条警告报成「unapproved」，于是
`run-all-tests.sh` 恒定退出 1，CI 恒红。

## 根因

诊断名解析只认 swiftc 的 **OSC-8 超链接**形式：

```perl
print "$1\n" if /\e\\([A-Za-z]+)\e\]8;;/    # 只匹配颜色输出
```

但闸门自己传了 `-Xswiftc -no-color-diagnostics`。本机实测（Xcode 26 /
Swift 6.4，hexdump 验证）：该参数下输出是纯文本 `[#DeprecatedDeclaration]`，
**零 ESC 字节**。于是每条警告都落进 `(unclassified)` 兜底，allowlist
永远匹配不上——包括它自己写的条目。

这个 bug 的形状值得记住：**闸门的豁免机制和它的解析器互相不兼容**，
而两者都在同一个文件里，谁都没被单独验证过。

## 修复

- 解析改为同时支持纯文本 `[#Name]` 与 OSC-8 两种形式，外加固定宽度列兜底
- 逻辑抽成纯函数（`warn_diagnostic_name` / `warn_is_allowlisted` /
  `run_warn_gate`）+ `BASH_SOURCE` 守卫，使其可被 source 后直接测试
- 新增 `scripts/test-warn-gate.sh`（**18 项**），其中一项直接复现生产故障：
  「只有 allowlist 警告 → 应退出 0」，修复前返回 1
- 接入 `run-all-tests.sh` 且**置于闸门之前**：解析器回归会给出明确原因，
  而不是留下三个神秘警告让人自己猜

## 独立复核推翻了 subagent 的结论（方法论记录）

派出去核查 allowlist 的 agent 给出一个斩钉截铁的结论：**「废弃的
`kCFStreamPropertyHTTPSProxy*` 可以安全删除」**，并附了对照实验数据。

**结论是错的，而且方向相反。** 它的实验被一个陷阱污染了：它把假代理放在
loopback（`127.0.0.1`），而本机 `scutil --proxy` 的 `ExceptionsList` 里恰好
含 `127.0.0.1`——**CFNetwork 对 loopback 目标会绕过配置代理、改走系统配置**。
于是 `kCFNetworkProxiesHTTPS*` 探针返回 310 而空字典反而成功，这个反转正好
制造出「只有废弃键才生效」的假象。

换用非例外地址复测（LAN `192.168.31.204` + 一个无人监听的端口，判定标准为
「代理被采纳 → 请求必然失败」），三轮结果完全一致：

| `connectionProxyDictionary` 内容 | CFNetwork 是否采纳 |
|---|---|
| `kCFNetworkProxiesHTTPSEnable/Proxy/Port` | 是 |
| `kCFStreamPropertyHTTPSProxyHost/Port`（废弃） | 是 |
| 两者并存（当前组合） | 是 |
| 空字典 | 否（回落到系统配置） |

**两者等效，废弃的那对不是唯一保障。** 因此最终没有删键，而是：

1. 补上文档化的 `kCFNetworkProxiesHTTPS*` 三条，作为「文档化键若被 SDK 改坏
   仍不致绕过代理」的冗余（与原有 `HTTP*` 成对）
2. 改写 `ProviderHTTP.swift` 里那段错误注释，并写入测量陷阱本身——正是它
   误导了 agent，留着就会误导下一个读者

**教训**：agent 的实验结论必须连同**实验环境**一起复核。这次错的不是推理，
是测量——而测量错误会伪装成硬数据，比推理错误更难识破。

## 验证

`bash scripts/run-all-tests.sh` 退出码 0：guardrails → 30 项 guardrail 自测
→ 18 项 warn-gate 自测 → warning gate → 456 tests → 双目标构建，全部通过。
修复后另跑一次代理路由验证，3/3 轮确认 LLM 流量仍走代理。
