# V1.0 · 产品定义与验收标准

> 创建：2026-10-22 · 中枢（Claude）
> 用途：**"成熟产品"的尺子**。没有这把尺子，"成熟"就是各人各说的形容词。
> 本文的每一条都来自当前代码的实测，不是愿望清单。

---

## 一、这是什么产品

**一句话**：一个装在自己 Mac 上的邮件分诊机。早上打开两次，每次十分钟，把收件箱清到零。

**它是什么**：
- 单机 macOS 应用，进程内自带服务器（Swift + Hummingbird）、同步引擎与 SQLite 存储
- 只支持 QQ 邮箱（授权码 → IMAP 同步 → 阅读 → AI 摘要 → SMTP 回复 → 归档 / ⌘Z 撤销）
- AI **只读**：分类、解释、起草回复文本，**从不代替用户做任何写操作**

**它不是什么**（这些是刻意的非目标，不是缺口）：
- 不是 Gmail/Outlook 的替代品，不做多协议
- 不是团队协作工具，没有共享邮箱、没有权限模型
- 不是移动端
- **不是自动化的**：没有后台归档、没有自动退订、没有自动标记已读、没有 AI 自动发信

> 这条"不是"清单比功能清单更重要。产品成熟度的一个硬指标是
> **用户知道这个产品不会替自己做决定**。

## 二、三条核心承诺（每条都必须可验证）

| 承诺 | 含义 | 怎么验证 |
|---|---|---|
| **P1 · 十分钟清零** | 打开一次，一屏之内知道"还有什么要我处理"，处理完能确认"清干净了" | 简报页在**有未读 / 无未读 / 部分失败 / 同步出错**四种状态下，计数与列表必须一致且不矛盾 |
| **P2 · AI 只读** | AI 的任何输出都不能导致数据被改动 | 审查 `ai_actions` 审计表：每一条都有对应的用户触发；AI 路径上不存在写路由 |
| **P3 · 不撒谎** | 界面上说的每一句状态，都与后端真实状态一致 | 见第四节"六态与三个"不知道"" |

**P3 是本产品最容易破的一条。** 已经破过两次：
1. 账号找不到 → 告诉用户"授权码过期"（README 记为"这是个谎"）
2. 这个构建读不到钥匙串 → 又告诉用户"需要重新连接 / 邮箱设置不完整"（2026-10-22 实测，HB-02）

**验收口径**：任何一条横幅/状态，**先答"后端此刻的真实状态是什么"，再写文案**。
写不出真实状态的，就该显示"不知道"，而不是猜一个。

## 三、信息架构（当前形态，验收以它为准）

```
窗口
├── 左栏 导航（Sidebar）—— 地方，不是任务
│   ├── 智能视图：简报 / 收件箱 / 未读 / 置顶
│   ├── 地方：已归档 / 已发送 / 废纸篓
│   └── 我的分组（用户自己的聚合规则，带实时计数）
├── 中栏 列表（两种表面）
│   ├── 简报页：按 AI 分类分组，行内带只读建议
│   └── 收件箱页：原始列表 + 多种筛选（未读/置顶/分组）
└── 右栏 阅读器
```

**硬规则**：
- **同一个动词，在两个表面必须都存在、含义必须一致、行为必须一致**
  （"全部标为已读"不能在只有一个页面有；"置顶"不能在两个页面有两种行为）
- **同一个概念，只能有一个名字**（同一个用量面板不能有三个名字）
- **侧边栏是"地方"，弹出面板是"任务"** —— 归档/删除/清空这类动词不放在侧边栏

## 四、六态与三个"不知道"

每一个**会等待数据**的界面，必须显式处理这六种状态：

| 状态 | 必须做到 |
|---|---|
| 加载中 | 有可见的进度反馈；**不能转圈之后什么也没发生** |
| 空 | 一句人话 + 一个下一步动作 |
| 错误 | 说清**发生了什么** + **能做什么**；不能只给一个内部标签 |
| 离线 | 明示离线；动作要么禁用要么给出原因 |
| 未连接 | 有连接入口（不能指向一个不存在的地方） |
| 部分成功 | **报出真实的剩余数**（"还有 N 封未处理"必须是真的） |

外加三种"不知道"——**知道自己不知道**比假装知道更专业：

1. **未探测** ≠ **否**。（能力探测没跑过 ≠ 不支持）
2. **读不到** ≠ **不存在**。（钥匙串读不到 ≠ 用户没保存账号）
3. **没设过** ≠ **设成了 0**。（预算上限没填 ≠ 上限是 0）

## 五、设计系统（收敛目标）

**现在的事实**：`LagoonTheme`（颜色语义）、`LagoonSheetSize`（面板尺寸）、`LagoonMetrics`、
`LagoonTypography` 四套 token 存在，但视图层仍在大量写死字面量。

**收敛后的目标状态**：

| 类别 | 权威来源 | 规则 |
|---|---|---|
| 颜色 | `LagoonTheme` | 同一语义只有一个颜色；成功/信息/警告/错误四档固定 |
| 面板尺寸 | `LagoonSheetSize` | 同一类面板只有一个尺寸；不许各写各的宽度 |
| 间距/控件高度 | `LagoonMetrics` | 同一类控件只有一个高度 |
| 字号/行高 | `LagoonTypography` | 层级固定：列表行 / 分组标题 / 正文 / 辅助说明 |

**明令禁止**：
- 视图里写死 `#RRGGBB` 或 `Color(red:...)`
- 视图里写死面板宽度字面量
- 用颜色作为**唯一**的状态区分手段（未读标记必须有第二通道：形状/粗细/尺寸）
- 成功提示使用错误色系

**验收**：一条守卫测试，断言视图层不再出现上述字面量（源级扫描，必须做变异验证）。

## 六、无障碍底线（不是加分项）

- 未读状态：**不只靠颜色**；暗色模式下必须清晰可见
- VoiceOver：每个可交互元素有名字；**没有快捷键的命令不能留空的值字段**
- 动态类型：放大字号不破版
- 键盘：焦点环可见；焦点不会在操作后丢失
- 动作音效：不能"响 N 次"，也不能"该响不响"

- [ ] 所有批量操作报出真实剩余数

## 八、"成熟"的判据（终审用）

一个不是 demo、不是 hackathon 项目的产品，在**不知情的人**手里应该表现为：

1. 打开有窗口，不卡死，不报错，不显示内部变量名
2. 每个按钮按下去都有**可见的结果**，包括失败
3. 界面上没有一句话是假的
4. 关掉再开，状态还在
5. 出错时用户知道自己该做什么
6. 拿给别人看，说得出它是什么、为什么这样设计

**六条全中 = V1.0 可交付。缺一条都还在 V0.9。**
