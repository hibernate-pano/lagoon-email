### 2.4 解析器：实测无缺陷（并更正本节早先的一条错误结论）

> **更正**：本报告初稿在此写了一条"OSC-8 分支与 Swift 6.4 的 `\e\\` 形态失配、永不命中"的缺陷。**那条结论是错的**，已经实测推翻，错误的根源是我把 perl 正则里的 `\\` 当成了两个字面反斜杠，而它匹配的是一个反斜杠。

用真·构建日志逐行跑 `warn_diagnostic_name`（`bash -c 'source scripts/warn-gate.sh; …'`）实测：

| 断言 | 实测 |
|---|---|
| 分支 1 `\[#Name\]`（注释称"the production shape"） | **不匹配** —— 真日志里 `[#` 后紧跟的是 ESC，不是名字 |
| 分支 2 OSC-8 `\e\]8;;[^\e]*\e\\(Name)` | **分配合** —— 名字前字节为 `1b 5c`（ESC + 单个反斜杠），正是正则要求的形式 |
| 分类成功率 | 56 条去重警告中 **31 条**拿到确定名字（26 `SendableClosureCaptures` + 5 `DeprecatedDeclaration`），**25 条为空** |

关键点：`allowlist` 匹配的那个 `DeprecatedDeclaration` **是由分支 2 分类出来的**，不是分支 1。

顺带推翻一条脚本注释里的假设：`warn-gate.sh` 传了 `-Xswiftc -no-color-diagnostics` 并在注释里声称因此收到的是"plain `[#Name]`" 形态。实测闸门自己的构建日志（scratch-path + `-no-color-diagnostics`）仍有 **581 行含 ESC 字节**，即该标志并未去掉 ANSI/OSC-8。两条分支都被支持和测试，所以**不影响行为**；但注释里"plain 形态是 today 实际收到的形状"这一描述与事实相反。如果有人据注释删掉 OSC-8 分支，闸门会当场失效 —— 建议改注释，而不是改代码。

至于那 25 条空分类：逐条核对确认它们**真的不带任何 `[#` 标记**（非解析失败），全属 `main actor-isolated …` / `expression is 'async' but is not marked with 'await'` / `'@discardableResult' … is unnecessary` / `conformance … to 'Sendable' is unavailable` 四类，全部在 `Tests/`，而 `Tests/` 只对 `NoUsage`/`UnnecessaryEffectMarker` 设闸。方向安全（宁多报不漏报）。`Sources/` 侧无一条落入空分类。

> 本小节只改注释与文档；代码无需修。第 10 节原先列的"解析器失配"一项已删除。

## 6. 对三条"已知环境坑"的核实（一条被推翻，一条被澄清）

| 记忆中的说法 | 核实结果 |
|---|---|
| SwiftPM 必须加 `--disable-sandbox` | **本机已不成立。** `swift build --build-tests`（带沙箱）exit 0 / 14.20s；归一化转义后，带/关沙箱两次构建的警告 `file:line:col` 集合逐条相同（各 56 条，原始字节差异只来自 SwiftPM 进度文本穿插）；`run-all-tests.sh` 的裸 `swift test` 也跑满 864 个测试。建议改为"默认用沙箱，只有真的报沙箱错误才加 `--disable-sandbox`"，以免这条笔记掩盖真正的沙箱故障。 |
| `swift test --filter` 返回 "Executed 0 tests" 是假象，必须跑全量 | **原因是口径，不是 bug。** 每个 target 单独跑一遍 `Selected tests`，未命中的 bundle 自然报 0。实测 `swift test --filter RefreshGateTests`：`LagoonTests` 报 `Executed 5 tests`，另外三个 bundle 报 0 —— 过滤是生效的。正确读法是**只看 `Test Suite 'Selected tests'` 里非零的那一行 / 匹配 bundle 的汇总**，不能把"存在 0"当成"跑了 0"。本体检仍按全量执行，结论不受此影响。 |
| 不要 `rm -rf .build`；强制全量重编用 `find … -exec touch {} +` | **遵守。** 全程未删 `.build`，两次全量重编均用 touch 实现（46.72s 与 14.20s 那两轮）。 |

## 9. 本次实测发现的一个真缺陷：警告闸门的「符号链接假绿」

**影响范围：本仓库当前不受影响（已核实）；但闸门本身埋着一个静默失效路径。**

### 现象

同一条构建日志（内含真实 `#NoUsage` 警告），只改变调用时的当前目录写法：

| 调用方式 | `run_warn_gate` 结果 |
|---|---|
| `cd /tmp/lagoon-baseline/mut && bash scripts/warn-gate.sh` | ✅ `no unapproved warnings`，EXIT=**0** ← **假绿** |
| `cd /private/tmp/lagoon-baseline/mut && bash scripts/warn-gate.sh` | ❌ `1 unapproved compiler warning(s)`，EXIT=**1** ← 正确 |

### 因果链

1. macOS 上 `/tmp` 是符号链接（`/tmp -> private/tmp`）。从 `/tmp/…` 进入仓库时，bash 的 `$PWD` 保持**逻辑路径** `/tmp/lagoon-baseline/mut`。
2. `scripts/warn-gate.sh:153` 用 `local repo_root="$PWD"` 作为归类基准。
3. 但 swiftc 在诊断里输出的是**已解析的物理路径** `/private/tmp/lagoon-baseline/mut/Sources/…`。
4. `scripts/warn-gate.sh:182-189` 的分类靠前缀匹配：
   ```bash
   case "$file" in
     "$repo_root"/Sources/*) ;;            # 命中 → 纳入闸门
     "$repo_root"/Tests/*) …               # 命中 → 按两类设闸
     *) continue ;;                        # ← 逻辑≠物理时全部落到这里，静默丢弃
   esac
   ```
   物理路径不以逻辑 `$repo_root` 开头，于是**每一条警告都被当作"不属于本仓库"而 continue 掉**，包括 `Sources/` 下的。结果：警告越多照样全绿，`violations` 恒为 0。

失效方向是本报告里最坏的一类：不是误报逼人修（那会被发现），而是**无声地把硬闸门变成 no-op**。它是本仓库历史问题（"常红被忽略"）的镜像面 —— 那次是红得太响被无视，这次是绿得太安静无人知。

### 为什么两道自测机制都抓不到它

`test-warn-gate.sh` 的 fixture 是用 `$repo_root` **拼出**待匹配日志的（第 211、224 行 `$repo_root/Sources/…`），而 `$repo_root` 正是同一个匹配基准变量 —— 自测在测"自己定义的正确"，路径一致性是先写好的假设而非被验证的对象。真实构建日志里物理路径 ≠ 逻辑路径这一事实只有真跑 `swift build` 才会出现，而那恰是自测为了"无需 2 分钟构建"刻意避开的部分。这不是自测写得差，是它的构造决定了盲区。

### 本仓库为什么现在安全

```bash
cd /Users/panbo/Code/Demos/lagoon-email
[ "$(pwd)" = "$(pwd -P)" ] && echo SAME     # 实测：SAME
```

路径链 `/Users` → `panbo` → `Code` → `Demos` → `lagoon-email` 逐级检查**均无符号链接**，逻辑与物理路径逐字符相等。因此第 2、3、7 节的警告闸门结论成立，**本基线的绿色判定不因该缺陷作废**。

### 何时会被踩到

任何以符号链接形式访问仓库的调用：`cd /tmp/…`、`ln -s` 后用链接名进入、某些 worktree / 同步盘 / CI 缓存目录布局，以及以 `mktemp -d` 路径（`/var/folders/…` → `/private/var/folders/…`）为仓库根的场景。**开发者手工换一条路径进仓库跑一次闸门，就可能拿到一个不说明任何问题的 ✅。**

### 已修复（见第 12 节）

按"先让测试变红，再修实现"的顺序做完：

1. `scripts/test-warn-gate.sh` 新增 **3 条 fixture**，不靠 `$repo_root` 拼日志，而是在 `mktemp -d` 下造符号链接仓库根、喂**已解析物理路径**的日志（fixture 自己也要 `pwd -P`，因为 macOS 的 `mktemp -d` 在 `/var/folders` 下而 `/var` 也是符号链接）。旧实现下前两条**如期报红**（已验证），修后全绿。
2. `scripts/warn-gate.sh:153` 归一化基准路径：`local repo_root="$(pwd -P)"`。

三条 fixture 分别守住三个方向，缺一条都可能被"改过头"带偏：

| fixture | 守住的是 |
|---|---|
| `Sources/` 警告 + 符号链接 cwd → exit 1 | 修复本身生效（原为假绿） |
| `Tests/` NoUsage + 符号链接 cwd → exit 1 | 测试树设闸不因同样原因静默失效 |
| allowlist 条目 + 符号链接 cwd → exit 0 | **不能修成假红** —— 归一化后 allowlist 仍要命中 |

端到端复验（不仅靠 fixture）：在副本里重做 M4（`Account.swift` 追加 `let merged = 1`），从 `/tmp`（符号链接）路径跑真闸门 —— 现在正确报 `❌ 1 unapproved compiler warning(s)` 并 exit 1，而第一轮这里是 `✅`。

### 其余闸门是否同病

不同时。`ci-guardrails.sh` 与 `lint-no-silent-catch.sh` 匹配的是 `find Sources Tests` / `Sources/Lagoon/Views/*.swift` 这类**相对路径**，与 `$PWD` 是逻辑还是物理无关；第 7 节 M1/M2/M3/M5 正是从这个相对路径副本里跑红的，反证它们不受影响。**只有 `warn-gate.sh` 依赖绝对路径前缀匹配**，所以只有它有这个洞。
