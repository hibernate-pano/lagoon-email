# Lagoon 使用说明（V3：QQ 邮箱 · 单进程嵌入式）

> 这份文档告诉你：从零开始把 Lagoon 跑起来需要什么、每一步会发生什么、出错了怎么排查。
>
> Lagoon 目前只支持 **QQ 邮箱**（授权码接入）。闭环：同步收件箱 → 阅读正文 → Briefing 五分堆 → AI 摘要/回复草稿 → 回复发送 → 归档 / ⌘Z 撤销。
>
> 架构是**单进程**：服务端（Swift/Hummingbird）和 SQLite 存储全部内嵌在 `Lagoon.app` 里。没有 Docker、没有 Postgres、没有 launchd、没有 `.env`。数据只落在这台 Mac 上。

---

## 一、你需要准备什么

| 需要什么 | 说明 |
|------|------|
| 一个 QQ 邮箱 | 在 QQ 邮箱设置里开启 IMAP/SMTP 服务（见下） |
| 一个 **16 位授权码** | 不是 QQ 登录密码，专门给第三方客户端用 |
| Mac（macOS 14+） | 应用是原生 SwiftUI |

日常使用只需要 `dist/Lagoon.app`；从源码跑见第四节。

## 二、QQ 邮箱接入（5 分钟）

### 第 1 步：拿到授权码（一次性，2 分钟）

连接页的第 1 步会直接给你这条路径，也可以点 **打开 QQ 邮箱设置页** 让浏览器带你过去：

1. 浏览器登录 [QQ 邮箱网页版](https://mail.qq.com) → 顶部 **设置** → **账号与安全**
2. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务** → 点 **开启**
3. 按提示做手机短信验证 → 页面弹出一串 **16 位授权码**（字母，一般没有空格）
4. 复制保存。**页面关掉后不再显示**，忘了就重新生成一个（旧的立即失效）

### 第 2 步：在 Lagoon 里连接

1. 打开 `Lagoon.app` → 连接页第 2 步填 **QQ 邮箱地址** + **授权码** → 点 **连接**
2. 连接会转 1～3 秒：服务器先真的连一次 `imap.qq.com:993` 验证凭据，通过了才落库并开始首次同步
3. 授权码两端若有空格/换行会被自动去除（浏览器复制常带尾巴）

连接成功后：

- 工具栏账号菜单里能看到账号和**状态点**：🟢 同步正常 / 🟡 失败重试中 / 🔴 需要重新连接（含义见第五节第 6 条）
- 邮件正文按需从服务器拉取，本地只存已打开过的——第一封打开会稍慢一点
- 详情页 **回复** → 编辑正文 → **⌘↩ 发送**（走 `smtp.qq.com:465`）
- **⌫** 归档（列表或详情按钮）
- **⌘⌫** 移到废纸篓；误操作 **⌘Z** 撤销（远端也会移回收件箱）
- 一键退订：Briefing 里的订阅噪音直接退订（RFC 8058 / 自动确认，全程可撤销性除外——退订不可撤销）

### 日常用起来的几件事

- **左侧导航栏**：智能视图（简报 / **收件箱** / 未读 / 置顶）、位置（已归档 / 已发送 / 废纸篓）、以及你自己建的**分组**（按发件人或主题关键词自动归类），每项带实时计数。点条目即切换，不用再开弹层找位置
- **「收件箱」就是收件箱**：这个列表只含**收到的、未归档的**邮件，**不含你自己发出的**——发出的信在「已发送」里。标题写「收件箱」就是为了说清这一点，不再用「全量邮件」这种名不副实的名字
- **已发送**：侧边栏「位置」里的「已发送」列出你从 Lagoon 发出的邮件，可搜索、可进详情、可批量操作。徽章上的数字是**下界**——只有打开过一次之后才知道，因为服务器 Sent 文件夹不参与日常同步。徽章为空不代表你没发过信
- **分组列表的标题就是你自己的分组名**：点侧边栏的「工作」，列表标题就写「工作」，不会跳到一个叫「我的分组」的通用标题上
- **分组可以改名，也可以改条件**：在「我的分组」面板里右键任意一个分组 →「编辑此分组…」，可以改名字、改按发件人还是按关键词、改匹配内容。改完侧边栏和计数会立刻跟着更新——建错了不用删掉重建
- **AI 建议就在列表行上**：有建议的邮件，行内直接显示「建议归档 · 判断明确」。点开看完整理由，可「忽略这条建议」——**只影响建议本身，邮件不动**。置信度低时会明说「不太确定」
- **列表密度**：列表工具栏的行高图标可切舒适 / 紧凑 / 密集，简报与收件箱共用同一设置（默认紧凑）
- **悬停预览**：鼠标停在某一行上约半秒，浮出只读卡片（发件人、主题、摘要、AI 建议）。不打开邮件、不标已读、不做任何改动
- **多选批量操作**：选中 2 封以上时底部浮出操作条（标已读 / 标未读 / 归档 / 移到废纸篓 / 取消选择），每个动作都可 ⌘Z 撤销
- **发件人排行**：⋯菜单或 ⌘K → 发件人排行。谁写来的邮件最多、多少封未读一目了然；可对任意发件人「查看邮件」或「归入分组」（按发件人自动分组）
- **搜索也匹配 AI 的判断**：搜「营销」「newsletter」「unsubscribe」这类词，能搜到正文里根本没出现该词、但 AI 已判定为该类别的邮件。搜索框下方常驻一行说明，不用猜结果是怎么来的
- **右键菜单**：两个邮件界面都有。收件箱界面的菜单含「置顶/取消置顶」，与简报页一致
- **一封信可以发多个人、还可以带附件**：新建邮件和回复都能填**收件人（多人，逗号分隔）/ 抄送 / 密送**，并**拖文件进来或点回形针选文件**。密送收件人**看不到**彼此（密送只进邮件信封，不进任何抬头）——所以填之前想清楚。附件单文件上限 25 MB
- **转发是「真的转发」**：点转发后，收件人收到的是**原邮件本身**——原来的格式、原来的附件、原来的抬头全都在，收件人的邮件客户端会像看一封正常的原邮件那样显示它（不是一串 `>` 引用）。你在转发框里写的话会加在上面
- **「设提醒」**：在邮件详情页点「设提醒」，或点 AI 建议里的「设提醒」，**你选时间**（明早 9:00 / 3 小时后 / 下周一 9:00，或自己挑），到点系统通知你。**AI 只提建议，绝不替你设**——时间是你的。提醒存在本机数据库里，**每次启动自动重新安排**（系统重启也不会丢）；⋯菜单或 ⌘K →「我的提醒」可以看全部、标完成、恢复、删除
- **简报会翻出老邮件**：超过 30 天没回的老邮件，只要还没读，会单独列在「需要回复」里（最多 50 封，超出会写明总数）——不会因为超出窗口就消失
- **简报页也能多选批量操作**：简报页选中 2 封以上，底部浮出操作条（标已读 / 标未读 / 归档 / 移到废纸篓）。⌘A 是**切换**——第一次全选已加载的邮件，再按一次回到空选，不会越选越多

### macOS 系统集成（V3.2 新增）

这个产品不只是「一个窗口」，它按 macOS 应用的样子来：

| 能力 | 在哪 | 说明 |
|---|---|---|
| **菜单栏** | 屏幕最上方 | 应用菜单（关于 / 设置 ⌘,）、文件（新建邮件 ⌘N / 收取新邮件 ⇧⌘N）、显示（切换主界面 ⌘0 / 循环密度）、邮件（搜索 ⌘F / 刷新 ⌥⌘R / AI 建议 ⇧⌘A / 我的提醒 / 操作历史 / 发件人排行 / 本月用量 ⌘B / AI 设置 / 命令面板 ⌘K）、帮助（快捷键 ⌘/） |
| **设置窗口** | ⌘, | 通用（语言 / 列表密度 / 提示音）、通知（新邮件提醒 + 跳系统设置）、账户（连接状态）、关于（版本 / 数据位置） |
| **Dock 角标** | Dock 图标右上角 | 未读数量，和侧边栏的未读数**永远一致**（同一个数据源，不会出现角标 12、列表 11）。超过 999 显示 `999+` |
| **系统通知** | 右上角横幅 | 新邮件到达时提醒，带发件人和主题；只在你**授权之后**才发。首次观察邮箱只记基线，不会把已有的几百封一次性弹出来 |
| **深链接** | `lagoon://` | `lagoon://message/<id>` 打开某封邮件、`lagoon://search?q=关键词` 打开搜索、`lagoon://unread` 跳未读。别的 App 或脚本可以调用 Lagoon |

> 通知和 Dock 角标在**窗口关掉之后仍然工作**——这是它们的全部意义，所以轮询在 App 级别，不在窗口级别。

### 出错了会看到什么

产品的错误反馈遵守一条规则：**标题说「什么失败了」，第二行说「为什么」，然后给一条能走的路**。

| 情况 | 你会看到 | 你能做什么 |
|---|---|---|
| 断了网 | 窗口顶部一条**淡黄色细条**：「离线 — 显示的是最后一次同步的邮件，新的邮件暂时收不到。」这是提示不是错误——屏幕上的邮件是真的，只是旧的 | 网络恢复后自动继续；不需要清缓存 |
| 网络恢复了 | 细条自动消失 | — |
| 邮件列表没加载出来 | 红色横幅「邮件列表加载失败」+ 第二行说明 + **重试**按钮 | 点「重试」 |
| 出了别的问题且重试没用 | 红色横幅 + 第二行说明 + **帮助**按钮 | 点「帮助」直接写邮件给开发者，邮件里已经带上了出错的具体信息 |
| 操作做成功了 | 底部浮出一块**可撤销的提示条**（6 秒后自动消失；鼠标悬停在上面时会**暂停倒计时**，方便你读完再点撤销）；不可撤销的操作则显示不带撤销按钮的提示条 | 6 秒内点「撤销」，或按 ⌘Z |

> 提示条上**永远有第二个按钮**：可以撤销的操作给「撤销」，不能撤销的给关闭。少了它，用户只能干等 6 秒。

### 哪些动作没有回头路

除了「彻底删除」，这个产品里的每个改动都能撤销（⌘Z）——**但只有 30 天以内**。撤销记录在服务器上保留 30 天，过期后 ⌘Z 就不再有东西可撤（动作历史面板会如实标出「已过期」）。下面这几个不是——**它们会真的动服务器上的邮件，且不可撤销**：

| 动作 | 在哪 | 说明 |
|---|---|---|
| **移到废纸篓（⌘⌫）** | 列表 / 右键 / 详情页 | 移入**废纸篓**，不是真删。废纸篓里的邮件可以「恢复到收件箱」，也可以拖到详情页重发 |
| **归档（⌫）** | 同上 | 移到服务器归档文件夹。**已归档里的邮件可以「取消归档」移回收件箱** |
| **彻底删除** | 废纸篓列表 / 行内右键 | ⚠️ **不可撤销**。永久删除服务器上的这封邮件，需要二次确认。只有已经在废纸篓里的邮件才能彻底删除 |
| **清空废纸篓** | 废纸篓面板 | ⚠️ **不可撤销**，一次清空整个废纸篓。面板会逐项回报成功/失败的数量 |

**永久删除的两道保险**：① 只能对已在废纸篓里的邮件执行（否则服务端返回 409）——不会出现"跳过软删除直接销毁"；② 走的是 IMAP 的 `UID EXPUNGE`（服务器如果不支持 UIDPLUS 就**拒绝执行**），所以绝不会误删其他客户端标记待删的邮件。

**能力不足时会提前禁用，而不是点了才报错**：连接邮箱时会协商该服务器支持哪些操作，并显示在「同步健康 → 查看详情 → 能力」里。如果账号没有废纸篓文件夹，「移到废纸篓」和 ⌘⌫ 会直接置灰；如果服务器不支持 UIDPLUS，「彻底删除」和「清空废纸篓」会置灰；如果没有「已发送」文件夹，打开已发送会明确告诉你**是这个邮箱没有这个文件夹**，而不是「加载失败」——后者会让人以为是网络问题、反复重试。鼠标悬停在置灰的按钮上会说明原因。

**两段式全选（⌘A）**：⌘A **只选当前已加载的邮件**，不会清空你看不到的那几千封。如果列表被截断，批量条上会出现一个链接「选择服务器上的全部 N 封」——点了才是全选匹配条件下的全部。**⌘A 再按一次退回第一阶段**，不会升级成更大的范围。这是为了避免"⌘A 然后 ⌘⌫"在毫无确认的情况下清空整个邮箱。

> **授权码安全**：授权码用 AES-GCM 密封后落库（密钥在本机 Keychain），**不会**出现在日志、错误信息或任何 API 响应里；`GET /api/accounts` 只返回地址、同步状态和能力，不返回凭据。

### 第 3 步：填 AI Key（V1 新增，2 分钟）

1. 点窗口右上 ⋯ 菜单 → **AI 设置**（或 ⌘K → AI 设置）。
2. 填 **MiniMax API Key**（接口地址和模型已预填，不用动），再填**每月上限（美元）**，点**保存**。
3. **保存即生效，不用重启 App。** 保存页会立刻告诉你结果：「已生效，AI 现在可以用了」= 服务商已经接上了；如果显示"已保存，但 AI 还是没能连上服务商"，说明是接口地址或模型名不对，改完再保存一次。

Key 只存本机钥匙串（`lagoon.envJSON`），不清零、不上传。清空 Key = 关掉 AI（摘要/草稿显示"AI 未配置"，邮件不受影响）。**清空后立刻保存，AI 马上关掉**——不用重启，也不用重装。

> **每月上限也是立刻生效的**。上限是关于钱的承诺：调高了马上能用新额度，调低了马上按新额度拦，所以它不能"重启后才算数"。

## 三、数据在哪、怎么备份

- 数据库：`~/Library/Application Support/Lagoon/lagoon.sqlite`（含 `-wal`/`-shm`）
- 密钥：全部在 Keychain（`lagoon.tokenKey`、`lagoon.bodyKey`、`lagoon.apiTokenSecret` 等），磁盘上没有含密钥的文件
- 想彻底重来：退出 App，删除上面的目录，重开（Keychain 密钥可保留，数据库会重建）

### 备份与导出（App 里的三个按钮）

打开 **⋯ 菜单 → 关于 Lagoon → 数据与备份**。这里有三个动作，不用退出 App，也不用命令行：

| 按钮 | 做什么 | 你会得到 |
|---|---|---|
| **打开数据文件夹** | 在访达里打开上面那个目录 | 直接看到数据库文件 |
| **立即备份** | 取一份**一致性快照**，你可以选存到哪 | **一个** `.sqlite` 文件，例如 `Lagoon-备份-2026-10-20.sqlite` |
| **导出全部为 .mbox** | 把本地已知的邮件逐封导出 | **一个** `.mbox` 文件，Thunderbird / Outlook / Apple 邮件都能直接导入 |

**为什么「立即备份」比自己拷文件靠谱。** 数据库跑在 WAL 模式：一次提交可能还留在 `lagoon.sqlite-wal` 里、没写进主文件。所以「退出 App，把 `.sqlite` 拷走」在写入发生时**会漏掉最新的邮件，而且不会报错**。备份按钮走的是 SQLite 自己的 `VACUUM INTO`，它在读快照上取一份完整副本，并且写出的是**单独一个文件**（没有 `-wal`/`-shm` 跟着）——这正是你能直接拷到 U 盘或新 Mac 上的东西。备份是**先写到临时文件、校验通过后才替换**的：失败时你原来的备份不会被动到，也不会留下一个看起来像备份的半截文件。

**导出范围。** 选「当前账户」只导出正在看的那个邮箱；选「全部账户」把所有已连接的邮箱合并进同一个文件。导出包含收件箱、归档、已发送和废纸篓里的邮件——「我收到的和发出的每一封」就是这个意思；结果里的封数会如实告诉你写了多少封、有多少封取不到（比如已经在别的客户端删掉了）。

**导出的邮件长什么样。** `.eml` 是服务器上的**原始邮件字节**（和详情页「下载 .eml」是同一份），格式、附件、抬头都在，不是从解析结果重新拼出来的。

**备份能还原吗？** 能：把那个 `.sqlite` 文件放回 `~/Library/Application Support/Lagoon/`，改名为 `lagoon.sqlite`（先退出 App，并删掉同目录的 `-wal`/`-shm`），重开即可。`.mbox` 则是给**换客户端**用的：在任何邮件客户端里「导入邮箱 / Import mbox」就能读。

> 备份文件里有别人的邮件——正文和 AI 草稿都是密文的（见下一节），但发件人、主题、时间、附件名是明文。**别把备份传到网盘或聊天软件里**，也别提交进任何仓库。

### 磁盘上的邮件长什么样

拷贝走那个 `.sqlite` 文件，就等于拷走了别人的邮件——所以这里写清楚**哪些是明文、哪些不是**：

| 内容 | 磁盘上是什么 |
|---|---|
| **邮件正文**（纯文本 + HTML） | **密文**（AES-256-GCM，密钥 `lagoon.bodyKey` 只在 Keychain 里） |
| **列表里的正文预览** | **密文**（预览本来就是正文的前几行，所以一起封） |
| **AI 草稿**（点「生成草稿」写下的那 3 个版本） | **密文**（同一把 `lagoon.bodyKey`） |
| 收件人 / 发件人 / 主题 / 时间 / 已读归档标记 | **明文**——它们是索引，列表和侧边栏的计数要靠它们 |
| 附件名、抄送/密送地址 | **明文**——属于元数据 |
| QQ 授权码 | **密文**（另一把密钥 `lagoon.tokenKey`） |

这不是端到端加密：密钥在你这台机器的 Keychain 里，拿到 Keychain 的人就能解密。它防的是「有人拷走了数据库文件」。

**所以请打开 FileVault**（系统设置 → 隐私与安全性 → FileVault）。元数据（谁发给你什么主题、什么时候）是明文的，FileVault 才是保护它的那一层。

搜索依然能搜到正文：密文在 SQLite 内部被解开后再比对，密钥不出进程。

**AI 草稿为什么也算密文。** 草稿是模型**照着这封邮件写的**——"关于贵方提出的开源维护者合作方案"这种句子，原封不动地出现在草稿里。所以草稿和正文是同一类东西：它带着别人邮件的内容，就和正文一起封。如果不封，拷走数据库文件的人虽然读不到正文，却能从草稿里读出正文的实质内容——那等于封了个寂寞。

**万一草稿被清掉了。** 极少数情况下（比如升级 App 时钥匙串里的密钥一时取不到），存着的草稿**无法加密**，这时 Lagoon 会把它们**删掉**，而不是让它们以明文留在磁盘上。草稿是可以重新生成的（打开那封邮件，再点一次「生成草稿」），所以删掉不损失任何邮件。App 会用一条横幅告诉你删了几份——不会悄悄清空。

**AI 会看到什么**：分类只发**发件人、主题和正文前 200 字**给模型服务商；摘要和草稿会发更多正文。这是唯一一处邮件内容会离开这台 Mac 的地方，在「AI 设置」里可以改。

诊断工具（读已连接账号，连真实 IMAP）：

```bash
swift run LagoonServerCLI --list-mailboxes    # 列出服务器上的所有文件夹
swift run LagoonServerCLI --self-test         # SMTP 发送→同步→归档→还原闭环（只发给自己）
python3 scripts/probe-qq.py <邮箱地址>         # 用授权码连一次真实 QQ，打印 Lagoon 会解析出的角色文件夹
```

CLI 走环境变量契约，两个密钥都必填：

| 环境变量 | 用途 | 要与 App 共享数据时 |
|---|---|---|
| `LAGOON_TOKEN_KEY` | 32 字节 base64，加密**凭据**用 | 取 Keychain 里 `lagoon.tokenKey` 的值 |
| `LAGOON_BODY_KEY` | 32 字节 base64，加密**邮件正文**用 | 取 Keychain 里 `lagoon.bodyKey` 的值 |

两个密钥是分开的：换其中一个不会让另一个失效。缺任何一个 CLI 都会拒绝启动（宁可不启动，也不要在没有密钥的情况下把正文写进明文）。

## 五、常见问题排查

**1. QQ 连接报「授权码被拒绝」**
→ 授权码不是登录密码；而且在 QQ 设置里**每重新生成一次，旧的立即失效**。去第 1 步重新生成一个再试。
→ 确认码是新的还报错：检查 IMAP/SMTP 服务是不是被 QQ 关掉了（长期不用会自动关闭），重新开启即可。
→ 这类错误会让同步状态进入 🔴 并**停止重试**（QQ 对连续失败登录会限流，所以是刻意不重试的）：重新连接成功后自动恢复。

**2. QQ 连接报「无法连接 QQ 邮箱服务器」**
→ 服务器连不上 `imap.qq.com:993`。先验证网络：`nc -vz imap.qq.com 993`。
→ 常见原因：公司网络/代理只放行 443。Lagoon 只走 **993（IMAP）和 465（SMTP）两个 implicit-TLS 端口，没有「跳过证书校验」开关**——这是安全边界，不会为连通性放宽。连接主机固定来自服务端 preset（`imap.qq.com` / `smtp.qq.com`），不接受任意主机。
→ 注意：如果你的代理开着 fake-ip 模式的 TUN，`dig` 出来的地址是假的（198.18.x.x），这不影响 Lagoon 本身连接，但会让你手工诊断时误判。

**3. 客户端显示 "Sync failed: …"，或者列表为空**
→ 先确认内嵌服务端在跑：`curl http://127.0.0.1:8080/healthz` 应返回 `ok`（若 8080 被占，App 会自动换 8081–8090，端口显示在「关于」里）。
→ 状态点变 🔴：授权码被拒，重新 Connect。

**4. 归档按钮是灰的 / 提示「没有可用的归档文件夹」**
→ 服务器在接入时协商过能力：既没有 `\Archive` 特殊文件夹，也没找到名为「归档 / Archive」的文件夹时，`capabilities.archiveFolder = false`，客户端据此禁用归档（服务端也会 409 拒绝，不会「半个归档」）。
→ 撤销入口（⌘Z / Undo 面板）**不受这个门控影响**——已归档的内容照样能撤销。

**5. 想验证归档/删除会用哪个服务器文件夹**
→ 跑 `python3 scripts/probe-qq.py`：它打印 QQ 返回的原始文件夹列表、modified UTF-7 解码结果，以及 Lagoon 当前匹配逻辑会选中的归档/废纸篓/已发送文件夹。中文文件夹名在 IMAP 协议里是 modified UTF-7 编码（`归档` = `&X1JoYw-`），这是国内邮箱兼容性最需要盯的点。实测 QQ 返回的是英文文件夹名（Archive / Sent Messages / Deleted Messages），所以这一层目前没有实际风险，但换服务商时仍要用这个脚本确认。

**6. 账号菜单上的状态点是什么意思？**
→ 数据来自 `GET /api/accounts` 的 `syncHealth`：

| 状态点 | 状态值 | 含义 | 服务器行为 |
|--------|--------|------|-----------|
| 🟢 | `ok` | 同步正常 | 持续同步（IDLE 或轮询） |
| 🟡 | `degraded` | 连续 3 轮失败，正在退避重试 | 1→2→…→300 秒退避（±20% 抖动）后重试 |
| 🟡 | `error` | 单轮失败（网络抖动等） | 同上，失败原因在菜单项里显示 |
| 🔴 | `needsReconnect` | 授权码被拒 | **停止重试**，重新连接后恢复 |

## 七、当前边界（明确不做的）

- **AI 只建议，不操作**：AI 读邮件、分类、解释、生成草稿文本。它不会自动归档/删除/退订/标已读，不会自己建规则，更不会发送邮件。所有改动都由你点击触发，并进入撤销记录
- **看 AI 建议**：按 ⇧⌘A，或从「⋯」菜单打开「AI 建议」。面板里每条建议会说明是什么邮件（营销 / 垃圾 / 工作 / 财务…）、AI 认为该做什么、以及它有多确定。你可以「忽略这条」或「查看邮件」——**面板本身没有任何会改动邮件的按钮**，归档和删除仍然在简报行和邮件详情页操作，由你亲手点
- 忽略一条建议后，即使 AI 重新分析这封邮件也不会再推给你
- 只支持 QQ 邮箱（Gmail 路线已移除；将来需要时作为新 feature 开发）
- iOS 客户端：未做
- 附件下载：已做，单个附件上限 25MB
- 发送附件：已做，单文件上限 25 MB，**不支持一次拖入几十个文件**（逐个选更稳）
- 转发：已做**真转发**（原邮件作为 `message/rfc822` 整体带过去，附件和格式都保留）。转发**不能再加附件**——转发件本身就是附件，加文件会变成两件事
- 提醒：只在本机（系统通知），**没有日历同步、也没有多设备**——换台电脑看不到你在这里设的提醒
- 正文本地缓存：已做，只存打开过的邮件（关闭后重开不再走网络）
- 邮件正文渲染不加载任何远程图片/外链资源（发件人无法据此知道你读过）
- 快捷键：⌘R = 回复，⇧⌘R = 回复全部，⌥⌘R = 重新读取当前界面（列表页 / 邮件菜单）；标为未读已修好，行菜单/⋯菜单都能用
- 通知开关：设提醒前要先在「设置 → 通知」里打开新邮件通知，否则提醒到点不会响——设提醒的界面会提示你
- 撤销窗口 30 天：30 天内的操作可以 ⌘Z 撤销或从「操作历史」面板里撤销；超过 30 天的记录会被标成已过期
- 操作历史面板分页加载：一次显示最近 100 条，底部会写「还有 N 条更早的记录」并提供「加载更早的记录」，不会悄悄截断；因为列表从新到旧排列，越往下翻越接近 30 天期限
- 撤销只有一份状态：从提示条按「撤销」和从操作历史面板按「撤销」走同一条路径——任何一边撤销成功后，另一边的提示条/列表行都会同步消失
- 分组（不是「规则」）：左边的「我的分组」里每一项都是一条**过滤条件**（按发件人或按主题关键词），不是一个会自己执行的动作。建新的用「分组…」菜单里的「按此发件人分组」/「按主题关键词分组…」；改已有的，在「我的分组」面板里右键它 →「编辑此分组…」（可以改名字、改匹配方式、改匹配内容）
- 详情页的「改分组为…」（简报里的分组）和侧边栏的「我的分组」是**两套不同的机制**：前者改的是「这封信归到简报的哪个分组」，后者是你自己起的名字、可以在侧边栏点开的一条过滤条件。两者都按发件人归类，但互不改写
- 「改分组为…」会先问你**改到哪、改多大范围**，默认「只改这一封」；选「改这个发件人的所有邮件」才会影响该发件人的每一封来信。确认框里会写出这个发件人的地址，改完后的提示也会说明这次影响了一封还是每一封
- 分发需要 Developer ID 签名 + 公证；当前包是临时签名（ad-hoc），仅限本机/可信机器
- 邮件数据不出本机；只有 AI 摘要/草稿的相关文本会发给你配置的模型服务商
