# 事故记录：2026-10-20 · 账号 id 修复误触真实库

## 一句话

一个 agent 把 CLI 的 `--db <path>` 当成了有效参数（实际不是），CLI 静默忽略它并对**默认路径的真实库**执行了迁移，用一把**随机生成、随后丢失**的 body key 封存了邮件正文缓存、列表摘要和一条 AI 草稿。

用户的**邮件本体没有丢**（QQ 服务器上是完整的），**元数据没有丢**（发件人、主题、时间、已读状态全部完好）。丢的是**本地缓存**，其中一条 AI 草稿无法自动恢复。

## 哪些能自愈，哪些不能

### 能自愈（只要 App 用一把新 body key 跑起来）

- **正文缓存（52 行）**：用户打开邮件时，`fetchBody` 走 `try? await BodyStore.get(...)` → 解密失败返回 `nil` → **自动从 QQ 服务器重新拉取**，并用新 key 重新加密写回。
- **列表摘要（345 行）**：`openSnippet` 解密失败返回 `nil`（**不崩溃**，列表照常显示，只是摘要行暂时为空）；下一次同步会从 IMAP 重新取 snippet，用新 key 重封。

### 不能自愈（1 条）

- **AI 草稿（1 条）**：`draft_replies` 不会自动重新生成——它只在 AI 摘要被触发时写入。原文在迁移前副本里完好（`["Hi Danielle，\n\n感谢跟进，我会查看链接并评估接入事宜，如有进展再与你同步。\n\npanbo-studio", …]`），**用新 key 重新封一次即可恢复**。

## 恢复步骤（需要一次交互授权）

1. 写入一把新的 body key 到 `lagoon.bodyKey`（Keychain）。
2. 用同一把 key 把迁移前副本里的草稿明文重新封好，写回 `draft_replies.variants`。
3. 启动 App：正文与摘要随使用/同步自愈；草稿当场可读。

**第 1 步在本机需要一次「允许访问钥匙串」的确认**——本机 `security` 工具与裸二进制都被 `errSecInteractionNotAllowed`（-25300）拒绝，`SecItemAdd` 返回 -128（用户取消），因为授权对话框由后台 `SecurityAgent` 承接而它没有可见窗口。

> 这正是本次 Keychain 修复（`KeychainBootSafetyTests`）要解决的同一类问题：**授权不可用时，产品必须给出可见的出口，而不是静默失败或永久挂起。**

## 已经落地的防线（防止同类事故重演）

| 防线 | 位置 | 作用 |
|---|---|---|
| **CLI 拒绝未知参数** | `Sources/LagoonServerCLI/main.swift` | 未知参数**立即失败**，且失败发生在打开数据库**之前**。`--db` 这种误用不会再被静默忽略，更不会写到真实库上 |
| **端口不再等待 Keychain** | `Sources/Lagoon/Services/EmbeddedServer.swift` | 钥匙串慢或被锁时，服务器仍然绑端口、App 仍然出窗口 |
| **有界读取 + 三态结果** | `Sources/Lagoon/Services/KeychainReader.swift`、`KeychainAccess.swift` | 5 秒超时；`.missing` / `.found` / `.failed` 严格区分——**读失败不再被当成"没有"**（旧代码会用 `"{}"` 覆盖用户存好的 AI 配置） |
| **锁住时给用户出口** | `Sources/Lagoon/Views/KeychainAuthorizationView.swift` | 「打开钥匙串访问」+「重试」，而不是一个不解释的转圈 |

## 一条教训

**工具的"沉默"比工具的"错误"更危险。**

`--db` 未知参数被忽略、CLI 照常对真实库跑迁移——没有报错、没有警告、退出码 0。如果当时 CLI 打印一行「未知参数 `--db`，本次将使用 LAGOON_DB_PATH 指向的真实库」，这次事故根本不会发生。

同样的道理在产品里成立：`.disabled()` 叠加、`try?` 吞错、`decodeIfPresent ?? false` 把"未确定"折叠成"否"——**每一个"沉默地继续"的地方，都是一次把用户推向错误结论的机会。**
